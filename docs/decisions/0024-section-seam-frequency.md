# 决策记录 0024：区块边界按节奏分级，雕刻花饰降频到断层

Status: implemented
Class: feature

## Problem

0020 让 `SectionMark` 承担区块分隔，并且**每个 `DetailSection` 都画**：一个详情页 9 个区块就是 9 条花饰，
首页两条。边界信号同时出现七件——112px 留白、440px 花饰、区块编号、24px 衬线标题、点线引导、
右端英文注记、上一块自己的收尾线——七件说同一句话，花饰于是从「事件」降为「节拍器」：

- 同级区块（01 档案 → 02 介绍 → 03 属性）之间画一条横贯 440px 的饰线，语义上等于宣布「这是两份文档」；
  同级之间正确的器件是留白尺度与标题层级，不是线。
- 390px 下空隙只有 52px，花饰取到下限 200px（内容宽 350px 的 57%），基线离上方页头收边线仅 26px，
  读起来又回到 0018 被否的那种「没画完的分割线」。
- 花饰位置硬绑「空隙恰好等于 `--space-section`」（`top: calc(var(--space-section) / -2)`），
  首页 hero 之后空隙来自 `padding-bottom`，于是 `HomeView` 必须单独覆写一次 `top`；每多一种特殊间距
  就多一处隐式契约。

## Decision

- **三档纵向节奏**（`tokens.css`）：`--space-section-tight`（`--space-section × 0.8`，详情页页头之后的首块）、
  `--space-section`（常规）、`--space-section-loose`（`× 1.4`，断层）。相邻块的间距仍由上一块的
  `margin-bottom` 给出；断层块另加 `margin-top`，两者折叠取较大者，故 `.block.seam` 的 `margin-top`
  写的是**最终间距本身**（写差值会被折叠吃掉）。首块（`.block:first-of-type`）上边距固定为 0，
  间距交给页头自己的下边距。
- **`DetailSection` 新增 `seam` prop**：只有带 `seam` 的区块渲染 `SectionMark`，并取放宽档。
  断层只放在换册处，**单页 ≤2 处、且只用于 ≥3 个区块的页面**：详情页 `stats`（文字档案 → 数据）与
  `skins`（玩法 → 藏品）、音擎 `props`（背景故事 → 参数）、关于页 `shortcuts`（管线 → 交互）与
  `rights`（站点 → 法务）。其余区块之间只有留白 + 编号 + 标题 + 点线引导。
- **花饰偏移与间距解耦**：`.section-head .section-mark` 读区块自报的 `--section-gap`
  （`top: calc(var(--section-gap, var(--space-section)) / -2)`），三档间距下都落在空隙中线。
  `HomeView` 改为把 `.banners` 的 `--section-gap` 覆写为 `--pad-section`，删掉原来的 `top` 覆写。
- **审计同步**：`composition-audit` 的 `headRule` 改判「`.seam` 区块必须带花饰、花饰形态合规
  （窄带 8–40px、宽 120px–头部 80%、水平居中、`aria-hidden`）、单页花饰 ≤2」，并保留
  「整轮一个花饰都没扫到判失败」，防止降频把判据退化成空转。

## Alternatives considered

- **保留每块一条花饰，只把尺寸调小**：频率问题没解决，且短花饰正是 0018 被否的形态——孤立短线
  比长饰线更像画坏的边。
- **全部撤掉花饰，只用留白**：首页 hero → 今日角色 → 目录 三处叙事断层会糊成一片；0020 已记录过
  用户明确要装饰属性，直接归零会把同一轮讨论重开一遍。
- **区块之间改画满幅水平线**：会与内容胶囊的收口线 / 上一块末行的线成对（0017 的坑），且同级边界
  用满幅线在语义上就是「两份文档」。
- **每块一条 40px 短刻线**：频率不变，只是把 440px 换成 40px；站内也没有「每块都必须断开」的语义依据。
- **用 `padding-top` 代替 `margin-top` 绕开折叠**：会与页头 `margin-bottom` **相加**而不是取大，
  页头间距要逐页归零；收益不抵复杂度，折叠语义本身是想要的（取大者）。

## Consequences

- 代价：花饰不再是每页的稳定节拍，改边界节奏要动 views 里的 `seam` 落点而不是纯 CSS；
  `--space-section-loose` 的正确性依赖「折叠取较大者」，写成差值会静默退回常规档。
- 收益：详情页花饰从约 9 条降到 0–2 条，边界信号从七件降到四件（留白 / 编号 / 标题 / 点线 + 英文注记）；
  390px 下花饰不再紧贴页头收边线；花饰位置与间距解耦，首页不必再单独覆写 `top`。
- 遗留缺口：「三档留白是否够、断层选得对不对」是视觉判断，自动化审不出来——`composition-audit`
  只守「≤2 且形态合规」，守不住落点是否成立。
