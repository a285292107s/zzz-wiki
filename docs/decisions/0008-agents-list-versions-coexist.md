# 决策记录 0008：代理人名录两版共存，版式是本地偏好而非 URL 参数

Status: implemented
Class: feature

## Problem

代理人名录（`/agents`）出了一版**卡片名录**：9:16 立绘格 + 图下标本签，一屏看到更多立绘
（几何与取景取自开发用的 `/calibrate` 角色网格）。旧版**表格名录**（`AgentsView.vue`：
一屏一行的四语名、`CatalogTable`）对「横向按列比对、复制姓名」更顺手，两者不是替代关系。

三个约束决定了它不能简单地「换掉旧页」：

1. **两版都要活着**。任选一版删除，都会让一部分既有用法消失（卡片版没有四语名、
   也没有逐列对齐的横向比对；表格版看不到立绘）。
2. **选择必须只属于本人**。同一份 `/agents` 链接会被人复制、贴进群聊、被搜索引擎收录；
   把版式塞进查询参数（`?view=cards`）等于把「我喜欢的排法」当成这份资料的一部分发给所有人，
   还会让同一份名录出现两个可索引地址。
3. **不能为此多花一次首屏请求**。两版共用筛选、检索、排序读取、数据加载、卡片外壳等大量模块，
   为了选版式去动态 `import()` 其中一版，等于先读一遍偏好再决定下载哪份代码。

## Decision

**`/agents` 由外壳视图按本地偏好二选一渲染，偏好只落 `localStorage`，永不进 URL。**

- `src/views/AgentsRouteView.vue` 是 `/agents` 的组件：setup 期**读一次**偏好，随后
  `<AgentsCardsView v-if="agentsViewVersion === 'cards'" />`，否则 `<AgentsView />`。
  **两个版本都是静态 `import`**——所以首屏不会先闪一版再换另一版，构建产物里两版合并进
  同一个 `AgentsRouteView` chunk（`src/router/views.ts` 的 `/agents` 条目指向外壳），
  不产生第二次请求。
- 偏好单一事实源 `src/composables/useAgentsViewVersion.ts`：模块级 `ref` + 键
  `zzz-wiki:agents-view`，取值 `'cards' | 'table'`，**默认 `'cards'`**（新访客看到新版）。
  读取包在 `typeof localStorage !== 'undefined'` 里，写盘包 `try/catch`，非法值回落默认——
  与 `useHeroForm` 同一套写法。
- 切换入口是**设置页** `src/views/SettingsView.vue`（路由 `/settings`，`meta.title: '设置'`），
  同页也承载佩洛伊斯（1551）的立绘形态选择。控件是**选项板**：一组选项并排成方角板
  （`repeat(auto-fit, minmax(260px, 1fr))`，窄屏塌成单列），板上压一张 `aria-hidden` 的迷你样张
  ——版本组画陈列骨架（卡片版 9:16 立绘格 + 图下签条 / 表格版发丝行三段），形态组取真立绘
  （`heroGridSources` 的 `card/` 档，`retina: false`；样张仅 62 CSS px 宽，无需 `wide/`），
  右侧补一段详情页头图的文字骨架（两条横杠 + 三枚标签框），让「这一形态用在哪」在样张里就看得见。
  选中态三处同时表态：整板琥珀描边、板头 20×20 控件窗内的实心 `◈`、板头右端「已选」角标；
  未选只有 `◇` 与发丝线。`input[type=radio]` 承担语义、键盘操作与可访问名（`aria-label` =
  标签，一句说明挂 `aria-describedby`），选中态用 `:class="{ on: … }"` 而非 `:has()`。
  ⚠ **radio 不做 `.sr-only`**：它是 `position: absolute; inset: 0; appearance: none` 铺满整板，
  命中区就是那一块板——写成 1×1 的视觉隐藏控件会让 320px 命中区审计（`reflow-spacing` /
  `touch-targets`）直接判失败；焦点环挂在 radio 的 `:focus-visible`（板即控件的投影，
  环落在板框上），故键盘进来才有环、鼠标点选不留残留。
- **设置页顶替档案图谱的导航位**：主导航入口数受决策记录 0004 约束（979 断点由 6 个入口推导），
  故不是新增第 7 项，而是让使用价值低的**档案图谱整页下线**（`/atlas` 不再注册路由、不进 sitemap），
  位置让给设置：`catalog.ts` 的 `GUIDE_ENTRIES` 里设置升到第 06 位、`nav: true`，
  「数据说明」保持 `nav: false` 顺延为 07（编号是展示位次，站头与首页目录不允许空号）。
  于是入口是**站头导航第 06 位 + 首页目录第 06 行**，页脚只剩「数据说明」一处出处链接。
  设置仍**不进 `sitemap.xml`、不进按路由预载**（`generate-route-html.mjs` 的 `VIEW_OF`
  与 `STATIC_META` 都没有它）——偏好页对搜索引擎与首屏预热都没有价值。
- 卡片版的取景与档位**复用既有资产，不新增派生图**：`AgentCardGrid.vue` 的 9:16 格沿用
  `featured-pool.json` 的校准参数（`pos/zoom/originY`，与 `/calibrate` 网格同一套写法），
  图源走 `heroImageSources.ts` 的 `heroGridSources`（DPR<1.5 取 `card/`、DPR≥1.5 取 `wide/`，
  其后原图与同源 CDN 依次兜底）。未校准回落居中取景，缺立绘由属性图标垫底。
- 筛选/搜索的 URL 契约与旧版**逐字相同**（`useCatalogList` + `useCatalogSort`
  的 `id`/`name`/`rarity` 键与 `id desc` 默认值）——换版式不改变「同一份视图」在地址栏里的样子。
- **两版都不提供排序控件**（2026-10 调整：卡片版移除三颗排序钮，表格版表头不再可点排序）。
  陈列顺序取默认（编号倒序）；`?sort=&dir=` 仍照读，故**历史链接不会因为这次改动变成另一份视图**。
  移除的判据：卡片版里排序钮与标本签陈列挤在同一行工具栏；表格版则要靠「表头能点」这层暗示，
  与两版共用的「筛选 + 检索」工具栏不是一套语言。真要按姓名/稀有度逐列比对时，
  表格版的行对齐本来就够用。**音擎、驱动盘两个栅格名录页随后按同一判据一并移除**
  （判据不变：排序钮和同一行的筛选钮互相挤），`useCatalogSort` 仍为这两页算默认编号倒序、照读
  历史深链；屏上还留着排序入口的只剩邦布名录的列头，`CatalogTable` 的列排序能力原样保留；
  为栅格名录页造的 `SortButton` 因此没有调用方，一并删除（留着只会诱导下一个人把排序钮摆回来）。
- **签条上的长阵营名改由图标承载**（2026-10 调整，仍是卡片版内部的事）：阵营全名最长 11 字
  （罗斯凯利法·弗林特工坊），与「属性 · 职业」挤在 ~159px 的 nowrap 单行里必被省略号吃掉半截
  （1440 下实测 18 张卡有 7 张截断）。故阵营**移出签条**，在名字行右端占一枚 24×24 的图标位：
  位里贴本地阵营图标**原色原图**并铺满整格（图源走 `filterIcons.ts` 的 `campIconUrl`，与筛选下拉同一份
  本地资产，不经候选链），**不套外框**——原色徽记自带轮廓，再加一圈 1px 细线等于画两层边。
  **不做单色描摹**——第一版把图标当 CSS 蒙版、只留形状填灰，实测徽记糊成一团剪影、认不出是哪个
  阵营；徽记的辨识信息本来就靠形状加配色，故保留原色与原生尺寸。稀有度顺势从 24px 方框徽章改成
  签条行末尾的**纯文字**（`RANK_TO_TIER` 的 S/A/B，颜色走 `--rank-s/a/b`，字号字距与同行的属性、
  职业完全一致）——一行里其余两项都是文字，只有稀有度是画上去的方框，反而是它最扎眼、也最占宽。
  阵营名仍由这一位的 `title`、位内读屏文字与签条整行的 `title` 给出（`title` 现给全四项：
  属性 · 职业 · 稀有度 · 阵营名）；无本地图标时回落筛选下拉同款的细线圆圈占位，不把长名字塞回
  签条再截一遍。表格版与筛选下拉都不动（`Rarity` 组件与各详情页的徽章原样保留）。

偏好键由本记录钉住：

| 键 | 取值 | 默认 | 消费方 |
|---|---|---|---|
| `zzz-wiki:agents-view` | `cards` / `table` | `cards` | `AgentsRouteView`（`/agents` 外壳） |
| `zzz-wiki:hero-form` | `female` / `male` | `female` | `AgentHead`、首页今日角色、`AgentCardGrid` |

## Alternatives considered

- **版式写进 URL**（`/agents?view=cards` 或独立路由 `/agents/cards`）。**用户明确否决**，
  且理由独立成立：URL 在本站承载的是「**这份视图的内容**」（筛选、排序、详情参数），
  版式是**读者习惯**，不是内容；写进 URL 会让复制出去的链接替别人改界面，并制造两份可索引名录。
- **删掉旧版表格名录**。用户要求保留；且表格版承载卡片版没有的信息（四语名、逐列对齐的对照读法），
  删它等于用观感换掉一类实用场景。
- **动态 `import()` 选中版本**（懒加载其中一版）。要先读到偏好才知道下载哪份代码，
  于是首屏要么空一档、要么把外壳做成异步组件再加一层占位；而两版共用模块极多，
  各自单独打包等于把共用部分切两半。静态导入两版、合并进同一个 chunk，首屏零闪烁且无额外请求。
- **在详情页摆形态切换钮**（此前的做法）。同一偏好在多个地方各摆一个入口，必然出现
  「这页切了、那页没变」的错觉；且详情页动作行只承载返回导航，不摆形态入口。
  故形态入口与版式入口一起收进设置页，详情页/首页/名录卡片一律只读偏好。
- **给 9:16 格新派生一档专用图**（如按格宽重出的 `thumb`）。实测 9:16 取景只用掉源图约 28% 的宽度，
  `card/`（≤800px）本就是按「9:16 标本卡」定的档，`wide/` 覆盖高密度屏——新增一档等于
  再往仓库里沉 ~1.9MB，换不到可辨的观感收益。
- **新增第 7 个导航入口**（而不腾出位子）。会把导航入口从 6 个变成 7 个，直接推翻决策记录 0004
  里以入口数推导的 979 断点。故处置改为：让档案图谱下线、位置让给设置，入口数保持 6。
- **用原生 `<select>` / `:has()` 做选项板**。`<select>` 在暗色档案风里要额外重绘外壳且多一次展开；
  `:has()` 在本仓库其余处刻意不用（兼容性面），故选「铺满整板的原生 radio + 类名绑选中态」，
  键盘与屏幕阅读器语义都落在原生控件上。
- **只留发丝线选项行**（此前的做法，2026-10 调整）。一行一选项在宽屏上就是一张清单：
  选项名与右侧一个小菱形之间隔着半屏空白，读起来像目录条目而不像可点选的控件
  （用户反馈「一点都不像是选项」）。改成并排选项板 + 迷你样张后，「两个版式长什么样」
  在点选之前就看得见，选中的那一块板上也有三处表态（描边 / 实心标记 / 角标）。
- **单选标记用实心圆 `●` / 空心圆 `○`**（更眼熟的一对）。`●` 不在已子集化的 CJK 分片
  unicode-range 内，写了 `verify:fonts:cjk` 直接失败，而补字要重下重切全部分片、与改动不成比例
  （同决策记录 0004 拒绝写「韩」字的理由）。改成同形空心↔实心且已覆盖的 `◇` / `◈`。
- **给长阵营名配一份简称表**（或干脆留着省略号截断）。简称表是人工维护的第二份命名体系，
  且简称仍要挤进 ~159px 的单行——「罗斯凯利法·弗林特工坊」压到两字就认不出是哪家工坊，
  而截断等于每行都在赌用户记得住半截名字。阵营图标是既有本地资产，零额外维护。
- **图标单色描摹（当 CSS 蒙版填灰）**。这是第一版的做法，动机是「一屏几十张卡不成彩色贴纸墙」；
  实测徽记糊成一团剪影、认不出阵营（用户反馈「难以识别」），故改为原色原图铺满 24px：
  一屏之内每个图标也就指甲盖大，花不起来的顾虑不成立。
- **给图标套发丝外框**（第一版的做法，与稀有度徽章的框对齐）。原色徽记自带轮廓与留白，
  再套一圈细线就成了两层边，且 1px 框会把 24px 的位压成 18px 的画——用户要求「适当放大、去掉外框」。
- **卡片版签条行继续用方框徽章**（表格版与详情页的现行样式）。24px 的徽章要塞进 11px 的签条行，
  就得单独缩到 16px、再为它调 `vertical-align`（改前那 1px 行盒就是这么来的）；一行三项里唯独
  稀有度靠一个画上去的方框表意，与「文字 + 分隔点」的排法不统一（用户要求「和同行的属性、职业一样」）。
  故只在卡片版改纯文字，`Rarity` 组件在表格 / 详情 / 音擎 / 邦布等处照旧。

## Consequences

- 代价：`/agents` 多了一层外壳组件，两版的代码始终随 `/agents` 一起下载（用户只用一版）；
  偏好是**本机**的，同一台设备换浏览器/清缓存后回到默认卡片版，而「我上次选的是表格」无法跨设备跟随
  （这是约束 2 的直接代价）。
- 收益：两版都活着且都能被分享同一条链接；地址栏语义保持"这份视图的内容"不被个人习惯污染；
  首屏零闪烁、零额外请求；详情页少一个会与设置页打架的切换钮；不新增图片档位、不多占仓库体积。
- 遗留缺口：**没有埋点**，故「哪一版实际被用得多、多少人愿意进设置页改」无法回答；
  设置页只承载两项偏好，没有"恢复默认"按钮（默认值靠清除站点数据即可回到）；
  卡片版的渐进加载按首屏 18 条 + `rootMargin: 400px` 自动续载，未做「按稀有度/属性分组」
  之类的进阶陈列。
