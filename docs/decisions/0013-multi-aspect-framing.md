# 决策记录 0013：取景校准按画幅分开，hero 单独一个版式画幅

Status: implemented
Class: feature

## Problem

取景校准此前只有一套参数（`pos / zoom / originY`），是按 9:16 卡片调的。可这张图要出现在
三种展示格里：名录/首页的竖卡、详情页移动端头图、详情页桌面满栏横幅。前两者还能靠「同一套
相对构图套不同竖框」勉强复用，桌面横幅却只能退回**纯 `cover` 居中、不套校准**——同一张图在
卡片里脸在画面中央，在桌面横幅里可能被裁到边缘，且没有任何参数可调。

另一边，新页面会带来更多画幅（方图、横图、宽屏）。继续沿用「一套参数套所有画幅」的设计，
会撞上一个几何事实：**源图比画幅宽（S ≥ A）和比画幅窄（S < A）时，可用的取景杠杆不是同一对**。
源图窄于画幅时横向已铺满、`pos` 完全无效，纵向只能靠 `posY` 平移；此时一套按竖框调的
`pos/zoom/originY` 在新画幅里根本对不上焦。

## Decision

**校准表按画幅分开存，每个画幅一组四件套 `{ pos, posY, zoom, originY }`；9:16 是母版，其余画幅
由它派生起点；详情页桌面横幅单列一个非标准的 `hero` 画幅，且只平移、不缩放。**

- 画幅清单的单一事实源是 `src/utils/cameraRect.ts` 的 `FRAMING_MODES`：`9:16 / 3:4 / 1:1 / 4:3 / 16:9 / hero`
  （按画幅比升序）。渲染统一为 `cover` + `object-position: {pos} {posY}` +
  `transform-origin: 50% {originY}%` + `transform: scale(zoom)`；两个分支决定哪几个参数有效
  （S ≥ A 横向 `pos` / 纵向 `originY`+`zoom`；S < A 横向铺满、纵向 `posY`）。
- **`zoom` 下限恒为 1**：取景窗口不得大于源图，否则框外没有像素、卡片直接露底色。上限 3 是工具缩放手柄范围。
  迁入新形状时，历史 4 条 `zoom < 1` 的条目已钳到 1。
- 数据文件 `src/data/featured-pool.json`：`calibrated[id] = { inPool, modes }`，`modes` 的键即画幅；
  原 9:16 母版参数原样迁进 `modes['9:16']` 并补 `posY: '50%'`。顶层 `pool` 保留，它是
  `inPool=true` 角色的 9:16 取景派生值（首页「今日角色」读它），由工具保存时同步派生。
- **从 9:16 母版派生**（`deriveFraming` / `deriveHeroFraming`）：目标画幅取「能装下整块母版窗口的
  最小同画幅窗口」，横向对准母版中心；纵向装得下就居中、装不下则保住母版上缘（头部优先，留 2% 余量）；
  最后钳进源图。hero 的派生例外：只做 `cover` 平移、`zoom` 恒 1。
  派生只在工具的初始值里发生——`src/data/heroCalibration.ts` 的 `getCardFraming` / `getHeroFraming` /
  `getFraming` 对缺项返回 `null`，调用方回落居中；未落盘的「派生值」不会在运行时被解释。
- **`hero` 画幅 = 2.8:1（非标准，但由版式钉死）**：详情页桌面满栏横幅（文字浮于左半）在 ≥1200
  视口下 `aspect-ratio: 2.8`、盒高＝栏宽/2.8，与校准表 hero 画幅、`/calibrate` 成品预览同一比例——
  「校准所见即页面所见」。窄于 1200 的桌面窗口由信息块撑高（≈2.2–2.8），是已知偏差（文字不可裁优先）。
  这条定死是 2026-10 复核后补的：此前盒高随 `46vh` 漂移，16:10 窗口下比例落到 ≈2.48，
  与校准预览明显不一致（可琳 1061 实测）。
  hero 只消费 `pos` / `posY` 平移：版式横幅已整幅展示，缩放没有收益；共享元素飞行的目的地必须
  可预测，`zoom` 恒 1 让起飞前的原地变形只需复制一次平移。
- **运行时访问器按页面意图分**：`getCardFraming(id)`（9:16，名录卡片与详情页移动端头图）、
  `getHeroFraming(id)`（hero，详情页桌面横幅与首页飞行的目的地取景）、`getFraming(id, mode)`（任意画幅，
  供其他页面）。消费方：`AgentCardGrid.vue`（9:16）、`AgentHead.vue`（移动端 9:16 / 桌面 hero）、
  `FeaturedDeck.vue` + `src/utils/deckFraming.ts`（常态吃 `pool` 的 9:16 值，起飞前变形切 hero）。
- **`/calibrate` 工具**：六画幅切换；未显式校准的画幅进入时按 9:16 母版自动派生（标「派生值（未落盘）」，
  点「写入当前画幅」或调整后落盘）；调整自动保存（防抖 + 串行写队列，PUT `/__calibrate`；只提供拖框平移 / 拖角缩放两种操作，无滑杆）；
  hero 模式只能平移；「按 9:16 母版重派生」刷新起点；「入池」开关只在 9:16 模式出现（精选池只认 9:16）。

## Alternatives considered

- **继续一套 `pos/zoom/originY` 套所有画幅**。直接否掉的原因不是「不够精细」而是几何上不成立：
  源图窄于画幅时 `pos` 失效、纵向只剩 `posY` 可用，一套按竖框调的值在横画幅里既不能对横轴、
  也没存纵向平移量。桌面 hero 也就只能继续不做校准。
- **每个画幅都从零手调，不做派生**。六画幅 × 全部角色的起点都要人工定，换图或重调 9:16 母版后无法
  整批刷新；且各画幅的焦点会彼此漂移（同一张脸的横纵中心点对不上）。
- **hero 也用 16:9 这类标准画幅**。版式盒比是 2.8:1，套标准比例意味着上下额外裁切或在窄带里
  留白；实测这类偏差在满栏横幅上一眼可见。单列版式画幅、按实测盒比记，比把一个标准画幅硬塞进
  非标准盒子更诚实。
- **hero 也允许缩放、套 9:16 的 `zoom/originY`**。横幅本身已整幅铺满，放大只会裁掉场景、没有「消透明边」
  的收益；更麻烦的是共享元素飞行：目的地取景若带缩放，起飞前的原地变形必须复制同一缩放，飞行快照的
  内容尺度随之变化，交接处的尺度一致性就不再是可预测的常量。限定「只平移」把这段推理压成一个约束。
- **运行时按 9:16 母版即时派生缺项，而不是落盘**。页面表现会随母版与派生公式悄悄变化（改一处母版
  影响所有画幅），工具里也无法针对单画幅微调后再与页面核对。改为工具派生、显式落盘，缺项明确回落居中；
  「派生值（未落盘）」在工具里可见。

## Consequences

- 代价：数据从一套参数变成最多六套，每条角色一个 `modes` 对象；换图或重调 9:16 母版后要按画幅重派生
  再逐画幅目检；工具多出「派生 / 显式」两种状态和「重派生」操作，作者要理解这个区别。
- 收益：每个展示格都能取到为自己画幅调的构图；桌面 hero 的裁切可控，不再是纯 `cover` 居中；
  首页飞行的目的地取景可预测（只平移）；新页面只需调 `getFraming(id, mode)`，不用再动校准系统。
- 遗留缺口：`3:4 / 1:1 / 4:3 / 16:9` 当前没有页面消费，只有工具可调；hero 只平移意味着极窄横幅里
  可调的只有一个轴向（横向或纵向，取决于源图与 2.8 的关系），透明边/构图余量有限；未校准的新角色
  在所有画幅都以居中呈现，直到有人在校准表里落一笔。
