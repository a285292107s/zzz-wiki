# 决策记录 0006：分享入口归页面动作行，等级区块不再承载复制按钮

Status: implemented
Class: feature

> **已被 [0009](./0009-copy-link-button-removed.md) 取代**：复制链接按钮整体下线，分享回归浏览器
> 原生的地址栏 / 系统分享。下文是历史快照——它记录按钮一度如何收敛到「每页一个」，以及当时对
> 「删除该功能」的权衡；其中的显隐门禁与摆放位置已不适用于现况。

## Problem

详情页曾有**多个**「复制链接」按钮，且分散在数据区块里：角色页与邦布页的「复制此等级链接」
长在基础属性区的等级滑条面板里，音擎页另有一个「复制此精炼链接」长在精炼效果区。

三个问题：

1. **同页两个按钮复制的字节完全相同**。`useCopyLink` 一律 `navigator.clipboard.writeText(location.href)`，
   不带任何参数——音擎页的「复制此等级链接」与「复制此精炼链接」写进剪贴板的是同一个字符串。
   两个入口、一个出口，用户要自己猜该点哪个。
2. **按钮标签会撒谎**。标签写死了「此等级链接」，但复制的是整份 URL。当 URL 同时带 `?rf=`（精炼档位）时，
   点「复制此等级链接」得到的其实是一份精炼视图，标签与结果不符。
3. **按钮长在滑条旁边会改变滑条几何**。滑条是 `flex:1 + min-width:0`（独占收缩权），按钮是 `flex:none`；
   行内一挤，缺口全由滑条承担——1440px 下轨道 1022→887px，320px 下 158→23px（60 级压进 23px，刻度糊成一片）。
   而按钮的显隐条件恰是「等级非满级」，于是**用户第一次把滑条拖离满级的那一瞬**，轨道就被挤窄、
   滑钮在指针下跳到另一个值。此前用「按钮移到滑条下方 + 元信息行锁高 36px」压住症状，
   留下了一个专用插槽、一条只为压抖动的锁高规则和一段解释性注释。

## Decision

**详情页的分享入口是页面级动作，只存在于 `DetailPage` 的 `.page-actions` 行，每页一个。**

- `src/components/detail/DetailPage.vue` 在 `.page-actions` 内渲染 `<CopyLinkButton v-if="status === 'success'" />`，
  与「← 返回名录」同排；样式 `.page-actions { justify-content: space-between }` 把二者分列两端。
- **门禁是「档案已就绪」**，不是「等级非默认」。`.page-actions` 渲染在 `AsyncState` **之外**（加载中与 404 也会出现），
  故必须显式判 `status === 'success'`——否则 404 页会给出一个「复制这个坏链接」的按钮。
- `StatLevelPanel` **不再有 `#actions` 插槽**，连带删除 `.stat-level-meta > :deep(.copy-link)` 规则
  与「操作位会反复出现/消失」的注释；三个详情页（角色/音擎/邦布）的 `#actions` 具名插槽
  与音擎页的 `.refine-actions` 块及其样式一并删除。
  （元信息行保留 `min-height: 36px`，但理由已变：它不再是为了压住按钮显隐造成的抖动，
  而是等级行与数值表之间的固定呼吸带——理由已就地改写，不留失效注释。）
- **名录页（`/agents`、`/w-engines`、`/disks`、`/bangboos`）的既有门禁不变**：仍在
  `hasActiveFilter || !sortIsDefault` 时出现「复制筛选链接」。两处门禁不同不是双标——
  名录页是**导航入口**（分享它等于「去看名录」），详情页才是**被分享的那件东西**。
- 按钮的 `.copy-link` 类名、`CopyLinkButton` 组件、`useCopyLink` 组合式函数均未改动，
  故键盘可达性（focus + 回车 → 「已复制」）、打印态隐藏、剪贴板失败态等既有保障继续有效。

**语义随之从「导出视图参数」变为「分享此页」。** 这意味着默认等级、无任何查询参数的干净详情页 URL
现在也可一键分享——此前恰恰被排除在外，而那是最高频的分享场景。

## Alternatives considered

- **删除该功能**（起因：怀疑「使用率很低」）。**未采纳，且「低」这一前提本身未被证实**：
  站内只装了 `@vercel/analytics` 的 `inject()`，**没有任何自定义 `track()` 事件**，因此不存在点击数据，
  「使用率低」无从测量。且按钮提供的是纯快捷方式（能力上无独占）——桌面端用户可从地址栏自助取得同一 URL，
  **移动端才是它真正赚回成本的地方**：地址栏被截断、复制入口埋在分享面板里。在缺少数据的情况下
  按印象删除，风险高于保留一个实测仅 78×36px 的按钮。故保留，但收敛到每页一个。
- **留在等级滑条区块内**（用户已明确否决该位置）。除用户指出的「不适合」之外，客观理由是
  它的载荷是整份 URL 而非该区块的数据，放区块里必然要么撒谎（标签）、要么重复（同页多个），
  并且会持续参与滑条行的宽度分配。
- **`DetailHead` 的 `#meta` 槽**（稀有度/职业/阵营）。那里是**身份信息**，放动作会让「这条数据」与
  「对这份数据能做什么」混为一谈。
- **`.section-nav` 区块导航**。宽屏下它是 96px 固定侧栏、窄屏是吸顶横条——容器职责是导航，
  且宽度不足以容纳按钮文案。
- **`DetailPager` 底部翻页行**。详情页高 8000+px，放页底等于「想分享先滚到底」；
  与顶部动作行相比是同一个动作的两个极端位置，选顶部（页面身份所在处）。
- **站点页脚 `SiteFooter`**。职责是出处（数据源/版本/日期），且同样在页底。
- **悬浮按钮**。会在既有的 `.back-top` 之外再加一个浮动外壳，向模板站观感滑动。

## Consequences

- 代价：用户读到页面中段想分享时，需回到页顶（分享是**有意图的动作**，且按钮的独占价值在移动端，
  判定值得）。同页两个按钮合并为一个，音擎页用户不再能「分别复制等级与精炼」——
  但那从来不是两个不同的链接，只是两个不同的按钮。
- 收益：一个页面一个出口，标签与实际复制内容不再背离；`StatLevelPanel` 少一个专用插槽、一条只为压抖动的
  锁高规则与一段症状性注释，滑条行宽度不再受按钮显隐影响（那类「拖过满级边界时滑钮跳动」的缺陷整体消失）；
  干净 URL 也可分享。
- 遗留缺口：**仍无点击埋点**，故「分享入口实际被用多少次、移动端占比多少」依旧无法回答——
  本次是凭「纯快捷方式 + 移动端独占价值」的推理做的保留决策，不是凭数据。
  若要真正回答，需要新增 `track()` 事件（未在本记录范围内）。
  另外，`.page-actions` 位于页顶，移动端滚动后需回顶才可分享，未做「滚动时吸顶」的变体。
