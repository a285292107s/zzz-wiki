# 决策记录 0011：界面短文案也做四语，长文与静态产物仍是中文

Status: implemented
Class: feature

> 取代 [0010](./0010-multilingual-game-content.md) 中「**界面外壳保持中文**」那一半决策。
> 0010 的数据面部分（四语数据落在 `public/data/live/{lang}/`、切换入口在设置页、语言不进 URL）
> 仍然有效，本文不改写它。0010 把「界面多语言」列为被否决项，理由是它与
> [QUALITY.md](../../QUALITY.md) 的「无机器翻译痕迹」红线冲突、且体量是另一项内容工程；
> 本轮按用户明确要求把这条范围打开，并**如实修改那条质量项**（不再宣称界面文案无机器翻译痕迹）。

## Problem

0010 交付后，站点里出现了两种语言的**同一屏并置**：游戏内容随展示语言切换，而它周围的所有
中文壳（导航、筛选标签、表头、区块标题、按钮、空态、错误态、检索面板、设置页、标签页标题）
固定中文。对 en/ja/ko 读者，切换语言后看到的是「英文角色名 + 中文导航」的半成品。

难处不在「翻一遍」，而在四条约束：

1. **没有译文来源**。游戏术语（属性/职业/攻击方式）在源站有**官方译名**（`hakushin-raw` 的
   `element_type` / `weapon_type` / `hit_type` 值域），但站点自己的文案（导航、按钮、空态、
   错误提示…）没有任何官方译文——只能新写，且写完需要人工复核。
2. **红线要如实处理**。[QUALITY.md](../../QUALITY.md) 明确写「多语言质量 = 无机器翻译痕迹」。
   界面文案若靠 AI 起草，这条不能继续宣称成立，必须就地改成它真实的样子。
3. **布局与预算是算过账的**。站头有一份手算的断点空间账（320 档余量 18px）、主包 JS gzip 预算是 70KB
   （0010 交付时已用到 68.6KB——见 `verify-budget.mjs` 文件头的记账）、CJK 字体语料是按采集面全量裁剪的
   （采集面不止 `public/data/**.json`，见 `scripts/build/charset.mjs`）。
   日/韩文本长度与中文不同，任何一处都会动到既有不变量。
4. **静态产物是单语的**。sitemap、逐路由静态 HTML、`og:` 元信息都在构建期生成，只可能有中文一份。

## Decision

**界面短文案三语化（en/ja/ko），长文与构建期静态产物保持中文。**

### 覆盖范围

- **做**：站头/站尾、导航与目录、列表页与详情页的全部壳（区块标题、表头、筛选组与选项名、
  检索面板、分页、等级/突破标注）、空态与错误态、设置页自身、运行时的标签页标题与描述。
- **不做**：`/about`（数据说明）与 `/formulas`（战斗公式）两篇**站内中文长文**——它们是人工撰写的中文内容，
  不是界面壳。对非中文读者，页内挂一条「本页仅中文」注记（仅在 `lang !== 'zh'` 时出现，
  中文读者不需要这条）；`src/data/formulaGuide.ts` 与 `AboutView.vue` 的正文因此保持中文。
- **不做**：开发专属页面（`StyleGuideView` / `CalibrateView` / `devRoutes` 的页脚入口）——生产构建里被摇树移除。
- 语言无关的排版元素继续保留原样：`.en` 拉丁副标（AGENTS / W-ENGINES / DISK DRIVES / BANGBOO）、
  语言自称（中文 / English / 日本語 / 한국어）、`LOADING…` / `NO RECORDS` 这类等宽英文语气件。

### 机制：一条 `Loc` + 一张文案表

- `src/domain/lang.ts`：`type Loc = Record<Lang, string>` 是**四语齐全的类型强制**——少写任何一种语言
  都是编译错误；配套 `pickText(loc, lang)`（取当前语言）、`joinLoc(...)`（逐语言拼接，用于路由标题）、
  `isLoc(value)`（运行时判形，路由 `meta` 是弱类型袋子，取标题前必须先判）。
- 文案表落在 `src/domain/uiText.{zh,en,ja,ko}.json`（**中文清单是结构事实源**），
  `src/domain/uiText.ts` 用 `type UiText = typeof zh` + `const TEXT: Record<Lang, UiText>` 让其余三语
  逐键对齐（漏键编译报错；多键由 `tests/ui-text.test.ts` 的键集合断言补上）。
  取用三条路：`uiTextFor(lang)`（整棵树）、`uiLoc(path)`（取某条的四语 `Loc`，供路由表这种
  「先存 Loc、渲染时再按语言取」的场合）、`fmt(text, vars)`（`{n}` 占位符替换，让各语言自行安排语序）。
- `src/composables/useUiText.ts`：`const { t } = useUiText()` 给出**当前语言**的文案树（整树替换，
  不做逐键合并），模板里直接 `{{ t.list.code }}`；语言一变 computed 重算。
- **谁跟着结构走、谁进文案表**：与数据同处的标签不进文案表——属性/职业/攻击方式在 `domain/enums.ts`，
  类目与板块名在 `domain/catalog.ts`，技能槽位与数值面板名在 `domain/sections.ts`；它们用
  `pickText(x.label, lang)` 取。文案表只收「没有归属结构」的界面文案。这条分工写进了 `uiText.ts` 文件头。

### 游戏术语取官方译名，不自译

`ELEMENTS` / `PROFESSIONS` / `HIT_TYPES` 的 `label` 改为 `Loc`，en/ja/ko 三项**逐码取自源站官方值域**
（`hakushin-raw/{ver}/{lang}` 的 `element_type` / `weapon_type` / `hit_type`），锚点实测：

| 码 | zh（站内短式，未改） | en | ja | ko |
|---|---|---|---|---|
| 203 | 电 | Electric | 電気 | 전기 속성 |
| 201 | 火 | Fire | 炎 | 불 속성 |
| 300 | 流明 | Lumiflux | 流明 | 루멘 |
| 职业 2 | 击破 | Stun | 撃破 | 격파 |
| 职业 7 | 锋御 | Armorer | 鋭御 | 단조 |
| 攻击 101 | 斩击 | Slash | 斬撃 | 베기 |

`en` 同时是构建管线的规整值来源（`scripts/build/normalize.ts` 取 `label.en`），故改标签会直接影响数据面
写入的英文枚举值——这是有意保留的单一事实源。zh 保留站内已有的**短标签**写法（源站写「火属性/冰属性」），
本轮不顺手改中文标签。`tests/ui-text.test.ts` 守上表：**四语齐全（逐行非空）** + 三个精确锚点
（`ELEMENTS[203]` 全条、`PROFESSIONS[2].en`、`HIT_TYPES[101].ko`），**不是**把 18 行逐字钉死——
增删枚举值只改 `src/domain/enums.ts`，上表与本记录随之更新即可。

### 语言必须显式传进纯函数

`domain/sections.ts` 里凡产出**展示字符串**的函数改为收 `lang`：`buildSkillRows`、`buildBangbooSkills`、
`buildCoreSkill`、`synthesizePotentialCinema`、`characterStatsAtLevel`、`bangbooStatsAtLevel`、
`wEnginePropsAtLevel`；行对象字段 `zh` 改名 `label`（值已是当前语言）。与 0010 的口径一致：
语言显式传入，不读全局。

### 运行时的页面 meta

路由 `meta.title` 改为四语 `Loc`（类目/板块名直接复用 `catalog.ts` 那一份），`usePageMeta` 按
`useLocale` 解析标题与站名（`meta.siteName` / `meta.siteTitle` / `meta.detailSuffix` 进文案表），
故切换语言会即时改标签页标题。**例外是两篇中文长文**：`/about` 与 `/formulas` 的标签页标题仍是中文
（`AboutView` 给字面量、`FormulasView` 取 `FORMULA_GUIDE.title`）——它们与构建期静态 HTML
（`scripts/generate-route-html.mjs` 的 `STATIC_META`）逐字一致，而该脚本会回来对这两处做一致性自检，
改成变量即构建失败。页面是中文的，标题跟着中文，语义上也自洽。

### 复核状态（重要）

en/ja/ko 的界面文案是 **AI 起草**，未经母语者复核；`QUALITY.md` 的对应质量项已按此改写
（短标签：AI 起草、待人工复核；长文：中文原文；游戏内容：官方本地化）。术语一致性由
`ui-text.test.ts` 与 `docs/conventions/glossary.md` 的对照表承接，不做「已校验」的虚假声明。

## Alternatives considered

- **每组件就近写自己的小字典**（组件内 `const t = useText({…})`）：review 时更贴上下文，但 50 多个
  模板各写一份，没有任何「一处看全所有界面文案」的入口——而本轮文案**明确需要人工复核**，
  可复核性优先级更高，故选中集一表。
- **一条键一个 `Loc` 的大 TS 文件**（而非四份 JSON）：类型更直接，但译者拿到的是「四种语言交错」的文件，
  逐条复核时要在四条值之间来回切。四份 JSON + `typeof zh` 结构约束兼顾了「按语言交付」与「漏键编译报错」。
- **引入 i18n 框架**（vue-i18n 等）：能力和体量都超本轮需要，且与 AGENTS §0.2「不擅自加依赖」冲突；
  key 是字符串，运行期缺键只会静默回退，反而不如 `Loc` 的编译期强制。
- **界面文案交给机器翻译**：QUALITY.md 的原有红线直接禁止。本轮没有走这条路——新写的文案是**起草**，
  且把那条质量项改成「待人工复核」而不是继续宣称无机器翻译痕迹。
- **只对非中文读者显示中文原样 + 一句说明**（即 0010 的现状再补注记）：成本最低，但等于承认站点的壳
  永远只有中文；用户明确要求「把页面上其他中文也翻译成对应的语言」，故不选。
- **属性/职业标签继续用人工中文 + 只翻界面壳**：会留下「英文界面里属性写着『电』」的残留，
  正是本轮要消灭的半成品形态；改用源站官方译名后这类标签不再需要人工翻译。
- **把非默认语言做成 `import()` 懒加载块**（切语言时再取，主包回到约 82KB）：能省 ≈10KB gzip，
  是本次唯一被认真权衡的省钱手段。败在两处：① 省不掉机制本身（只带中文仍 82KB，预算照样要抬），
  省下的只是文案载荷；② 语言切换从此是**异步状态机**——启动要「读偏好 → await 块 → 挂载」、
  切换要「await 成功才提交」，失败态是「点了中文/日文但界面半中半外」，而这条正是本轮要消灭的形态。
  默认语言（zh）那条路两种方案完全一样，即收益只落在选了非中文的少数访客身上（首访 1.74MB 的 0.6%）。
- **把文案表当作数据面的一部分**（`public/data/ui/{lang}.json`，运行时 fetch，主包回到 ~70KB）：
  与 0010「一种语言一套数据面」的口径一致，且文案可以不入包。败在首屏要**先取一份文案再挂载**
  （每个访客多一次同源请求、多一个 RTT 的首屏延迟），fetch 失败还得有兜底文案（兜底就又把载荷搬回包里），
  并且 50 多个组件单测都要先装好这份文案才能断言——为一个可以静态编入的常量表引入这些耦合不划算。
- **语言进 URL**：0010 已权衡并否决（单地址 SEO 模型），本文不重开。本轮语言仍是本机偏好。

## Consequences

- 代价：**主包 JS 涨了约 10KB gzip**，故 `scripts/verify-budget.mjs` 的 `mainJsGzipKB` 由 **70 提到 96**，
  账记在该文件头与 `QUALITY.md` 的预算行。两套口径都记下来，避免再对不上：
  `verify:budget`（门禁）**90.5KB**、`vite build`（Vite 自己的 gzip 报告）**92.6KB**——差约 2KB，
  两条命令压的是同一个文件但压缩实现不同；引数字时**要连口径一起写**。
  归因（同一次 Vite 构建）：四语全量 ≈92.6KB / 只带中文 ≈82KB。**只带中文也有 82KB**，
  说明旧预算在这条设计下已不可达，是调整预算而不是藏起超支。
- 代价：**布局要按新语言重验**。ja/ko 的文案长度与中文不同（如「一覧」「등급」「Anomaly Proficiency」），
  站头断点空间账、窄屏区块导航、表格列宽都可能受影响。⚠ **这一条当时并没有做到位**：本记录初稿写
  「以 `viewport-overflow.js` / `reflow-spacing.js` 在四语下复跑为准」，但那两个脚本**没有语言维度**
  （不读写 `zzz-wiki:lang`，默认只在中文档跑），所以「四语下复跑」当时并不成立——四语走查只是
  一次性人工截图（名录/详情 × 三语），产物还在 gitignore 的 `temp/` 里。四语化第一轮复核查出
  的真实断点问题（en 在 980–999 档横向溢出、ja/ko 标签折行）正是靠那次人工实测才发现的，
  已按实测重算断点。**结论**：跨语言的几何风险要有带语言档的审计才算真守住，否则只是「中文够用」。
- 代价：**静态产物仍是中文**——sitemap、逐路由静态 HTML、`index.html` 的 `og:`/`description` 都在构建期
  生成，只有一份中文；运行时的 `document.title` 会随语言变，但「分享出去的首屏 HTML」不会。
- 代价：**新增字符要重切字体**。文案表是渲染面，故 `charset.mjs` 的采集面已从
  `src/**.{ts,vue}` 扩到**同目录下的 `src/**.json`**（此前只收 `public/data/**.json` 与
  `src/**.{ts,vue}`，`src/domain/uiText.*.json` 整类逃在字符集之外——只写在文案表里的字
  既不会进分片、也不会被 `verify:fonts:cjk` 的覆盖校验发现，因为门禁复核的是同一份字符集，
  只会报空真绿灯。这是本次复核发现并修掉的缺口，不是原有设计）。
  本轮已重跑 `pnpm run fonts:cjk`（字符集 5446 → **5454** 码点，251 片 / 1218KB，
  `noto-serif-sc.css` gzip 仍 14.7KB）；此后每次加新语言文案都可能再触发一次，
  `build:ci` 的 `verify:fonts:cjk` 会拦住漏跑——修好采集面之后，这句话才成立。
- 代价：**长文页对非中文读者仍是中文**，只是多了一条说明。这是范围选择的直接代价，用户已确认。
- 收益：**同一屏不再混两种语言**——切换语言后导航、筛选、表头、状态文案、设置页、标签页标题一起变，
  才是「选了一门语言」的样子。
- 收益：**游戏术语零自译**——属性/职业/攻击方式四语名取自源站官方值域，界面里出现的术语与游戏内一致；
  站内自有的文案集中在 `uiText.*.json`，可以整表交给译者或逐条复核，不必在模板里捞。
- 收益：**漏翻是编译错误**。`Loc` 让「加了新文案但只写中文」这件事在 `vue-tsc` 阶段就红；
  键集合/空值/占位符一致性另由 `tests/ui-text.test.ts` 守（10 条，含一条「槽位名对着数据面核」的
  防自译哨兵——见下方「复核发现的缺口」）。
- 收益：**顺手修掉两处语言相关的真相错误**——它们都是「按中文字面量处理已本地化的数据」：
  ① `sections.ts` 里「终结技」的识别原本写死中文，非中文页面会把终结技并回连携技那一行；
  ② `mechanismName()` 剥「基础倍率/倍率」后缀也只认中文，非中文页面会把派生技能名连后缀一起显示
  （`…Base Multiplier`／`基礎倍率`／`기본 배율`）。两处现在都按当前语言的写法匹配，
  英文侧由 `tests/sections-skills.test.ts` 的「Base Multiplier」用例守住。
- 遗留缺口：`public/data/**` 与文案表都已是四语，但**站点的社交分享元信息**（`og:title`/`og:description`）
  仍是中文单语（与静态 HTML 同源）。
- 遗留缺口：开发页（`/style-guide`、`/calibrate`）与 `viewTransition` 的调试日志仍是中文；
  它们不进生产构建，明确不在范围内。
- 遗留缺口：韩文正文仍走系统字体（Noto Serif SC 不含谚文，同 0010 的记录）；本轮新增的韩文界面文案
  同样如此。

## 复核发现的缺口（本记录落地后修补）

本轮实现完成后做了两轮代码复核，共修掉七处**门禁看不见**的问题。记在这里是因为它们分别代表一类
会重复出现的失败，而不只是一次性 bug。第一轮（静态通读）四处：

- **字体门禁的采集面漏了文案表**（详见上方「代价」那条）。`charset.mjs` 只收
  `src/**.{ts,vue}` 与 `public/data/**.json`，而文案表是 `src/domain/uiText.*.json` ——
  整类逃出字符集，于是「只写在文案表里的字」既不进分片、也不被 `verify:fonts:cjk` 发现
  （门禁复核同一份字符集，只会报空真绿灯）。已把 `src/**.json` 纳入采集面并重切字体。
  **教训**：新增「渲染内容的存放位置」时，要同时问一句「字符集采集面跟上了吗」。
- **槽位名自译**：韩文 `detail.skillChain` 原写 `연계 스킬`，而游戏官方韩文（数据面正文）写
  `콤보 스킬` —— 同屏行标题与组名两个叫法。已改正，并新增 `tests/ui-text.test.ts` 的哨兵：
  直接拿 `public/data` 里各组名前缀核对六类槽位名，防「自译」重新溜进来（该用例做过负向验证：
  把 `연계 스킬` 改回去会红）。
- **模板里残留的中文**：音擎名录的「满级 Lv.{n}」「精炼 {n} 阶」、潜能徽标「潜能{lv}·{kind}」、
  技能表 `sr-only` caption、「着装 · {n}」「显示更多」、以及角色详情的 meta description 站名。
  前两处尤其值得记：`t.detail.refineRank` 当时**已经存在**并在详情页用得正确，卡片上却另写了
  一份内联中文——同一条文案的第二份实现，是「改了一处忘了另一处」的典型。
- **最近访问的标签只存了访问当时那一种语言**：名字是随语言解析出来的，只存单串会让读者切到
  别的语言后一直看到旧语言的名字（且写进 `localStorage`，刷新也不消失）。现在按语言分别记录，
  且**以当前语言的检索索引为准重查**（索引是按语言构建、条目齐全的单一事实源），存档值只作兜底。

第二轮复核（对着浏览器实测）又找出三处，都是**只算中文就会漏掉**的类型：

- **日文数据的招式名带注音标记，被裸插值印到页面上**。`public/data/live/ja/**` 里 377 处
  `<ruby=よみ>漢字</ruby>`（zh/en/ko 实测 0 处），其中名字类字段 371 处：`skill.*.description[].name`
  246 处（basic 61 / special 60 / assist 55 / dodge 39 / chain 31）、`passive.level.*.name[]` 112 处、
  `talent.N.name` 13 处。说明文字一直走富文本工具，
  但**组名/被动名/影画名是裸插值**的（`SkillGroup`、`CoreSkillGroup`、`AgentDetailView` 的 DescRow），
  于是日文详情页的行标题直接显示 `回避：<ruby=むゆうほ>夢遊歩</ruby>` —— 违反 §3 富文本铁律。
  已在这三处过 `stripRichText`（剥壳留文 → `回避：夢遊歩`），并加用例：组件级测「行标题不含 `<ruby`」
  且汉字本体仍在（含负向验证：还原裸插值即红）。
  **教训**：富文本铁律的检查面是「**所有**游戏文本渲染点」，不只是描述段落——名字字段同样是游戏文本。
- **终结技识别只认方括号，en/ja 仍会把终结技并回连携技行**（上面「顺手修掉」那条其实只做了一半）。
  四语数据的引用包裹符并不同：zh/ko 用 `[终结技：残心]`，ja 用直角引号 `『終結スキル：残心』`，
  en 干脆没有括号（`…automatically after Ultimate: Zanshin:`）。改成「槽位名紧邻冒号」即命中
  （至多允许一层引号/方括号），四语实测都成立；`tests/sections-skills.test.ts` 的用例扩成四语参数化，
  负向验证下旧判据恰好只让 zh/ko 通过、en/ja 失败——正是报告里的现象。
  **教训**：把写死的中文换成「当前语言的写法」还不够，**标点与包裹符号也要一起换**。
- **顶栏的空间账只按中文算，en/ja/ko 折行/溢出**。站头的主排导航与站名会随语言切换文案，
  但字距（0.22em / 0.06em）与内边距是按 CJK 短标调的，压到拉丁文/韩文上是纯浪费；实测
  en「New Eridu Data Terminal / W-Engines / Combat Formulas」在 980–999 档会让**文档横向溢出**
  （文档宽 994 > 视口），ja/ko 则在断点边界把标签折成两行、站名折成三行（截图确认，整排读成
  「代理 / 人」「ドライブディ / スク」）。修法两步：① 非中文档经 `html:not(:lang(zh))` 还原字距与
  内边距（只动字距不动字号，层级不变）；② 断点由 980 提到 **1000**（= 最长语言 en 的一行放下所需
  最小视口），导航只在真放得下时出现，否则整排收进 ☰。四语 × 980–1060 逐档实测：0 折行、0 溢出。
  **教训**：`SiteHeader.vue` 里那笔手算空间账（品牌 + 导航 + 工具组）从此**必须按最长语言算**，
  每加一种语言都要重算——这也正是它当初写 720 会坏、后来写 980 仍会坏的原因。

另有两处（同一轮，体量小但同属「只按中文写」）：

- **英文首页把站名印了两遍**：hero 主标题 = `t.meta.siteName` + 固定的拉丁装饰行
  `Ropeweb Archive`，而 en 的 `siteName` 本身就是这串 → 英文读者读到
  「Ropeweb Archive / ROPWEB ARCHIVE」。已按**值相等**跳过装饰行（不按语言硬编码）。
- **清掉两个没人用的文案键与一段死 CSS**：`common.backToTop` / `search.close`
  （组件实际用的是 `backToTopSr` / `closeSr`，全仓 0 引用）与 `SettingsView.vue` 里
  给不存在的 `<b>` 写的 `.lang-current b`。文案表四语同步删，仍为 217 键。
