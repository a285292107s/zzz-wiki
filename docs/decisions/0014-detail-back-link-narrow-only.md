# 决策记录 0014：详情页「返回名录」只在窄屏出现

Status: implemented
Class: simplification

> ⚠ [0029](./0029-mobile-bottom-bar.md) 之后窄屏也有固定底部栏、当前类目可点，
> 「窄屏没有品类入口」这一前提已不成立；结论（返回链接仍只在窄屏出现）暂保留：
> 详情页头需要一个明确的局部出口。它与底栏当前类目指向同一处，属已知的第二入口。

## Problem

四个详情页（代理人 / 音擎 / 邦布 / 驱动盘）共用 `DetailPage.vue` 的页头动作行。该行只承载一个
「← 返回名录」链接，是页头唯一的流内元素，且它买不到独占能力：站头主排导航自 1000 起常驻，
当前类目高亮、一键即回同一份名录。

代价却落在首屏最贵的位置——1440 下它等于 `0.9 × --pad-section`（78px）页首留白 + 26px 行高 +
32px 下边距 ≈ 136px，全部压在封面之前。窄屏相反：主排导航收进底部栏（0029），
站内没有别处再给出品类入口。

## Decision

- 详情页动作行只在 `<1000` 渲染；`≥1000` 不出现，页首留白同时从 `0.9 × --pad-section` 收到
  `--space-group`（26–42px），封面接在站头下沿。
- **断点必须与站头主排导航的 1000 同值**（`SiteHeader.vue` 的 `max-width: 999` 与
  `min-width: 1000`）：站头能给出品类入口的宽度，就是页头不必再给一遍的宽度。改任一侧都要同改另一侧。
- 窄屏行为一字不变：动作行、链接文案、命中区、间距全部照旧。
- `scripts/audits/keyboard-journey.js` 的返回链接断言拆成两段：1440 下断言动作行不渲染且站头
  当前类目指向 `/agents`，768 下断言返回链接可聚焦。守的对象随断点一起换，断言总数不变。

## Alternatives considered

- **搬到宽屏左侧固定索引列的顶部**（滚动全程可见，比现状更强）。否决：索引列宽 96px，
  「返回驱动盘总览」这类 7 字标签放不下，四类目 × 四语言都要另立短标签——为站头已有的入口再养
  一套文案与排版约束，结果仍是第二处入口。
- **只压缩页首留白、保留动作行**：省 78px，但那条孤零零的链接仍占首屏一行，且指向的正是站头
  高亮的那一项。
- **连窄屏一起删**：否决，窄屏没有站头主排导航，页头这一条是主要内容出口。
- **改写成面包屑**（「代理人 / 妮可」）：占同样一行，空间账不变，只是换了措辞。

## Consequences

- 收益：宽屏首屏多出约 70–95px（视口越宽越多）；加载失败 / 404 时，页头链接与错误态里的
  「返回名录」不再同屏重复。
- 代价：宽屏少一条显式「返回名录」文字，读者须认出站头高亮类目可点，或按浏览器返回。
  分享链接首访者（无历史可退）在宽屏靠站头，窄屏靠页头链接。
- 可观测：`≥1000` 的详情页不再有可见的 `.page-actions`；打印态无变化（站头与索引本就在打印时隐藏）。

> 后续演进：[`0021`](./0021-detail-rail-width-follows-locale.md) 把索引列改为随语言自适应（96–152px），
> 上面「索引列宽 96px、7 字标签放不下」的宽度前提已失效；结论不变（返回链接仍只在窄屏出现，
> 页面动作不进区块索引）。
