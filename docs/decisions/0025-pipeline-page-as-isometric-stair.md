# 决策记录 0025：数据链路图用「等距台阶」而不是流程图

Status: implemented

Class: feature

> 已被 [0027](./0027-architecture-page-as-zoomable-atlas.md) 取代：这一页现在只剩一张可缩放的系统地图，
> 本记录描述的装置已随重构删除，保留它是为了记住当时的取舍。


## Problem

站点此前把「数据从哪来、怎么进来、怎么被读到」这件事拆散在三处：`/about` 的编号小节里是四段
文字步骤、页脚是一行数据版本、`DATA_GUIDE.md` 是给维护者看的管线文档。读者要拼出整条链，得自己
把这三处合起来读。三个具体缺口：

1. **没有形状。** 四段文字步骤读起来是一条平铺的清单，「外部源 → 抓取 → 门禁 → 本地」的**方向感与纵深**
   （越往下一步越靠近本站自己的文件）在文字里丢失了。
2. **层的边界与真实代码不符的地方没人讲。** 例如门禁并不在抓取脚本里（脚本内两道只告警，硬卡点在
   自动任务里），字体子集先于门禁跑。这些是「一眼看不出来、但影响读者判断」的事实。
3. **读者不知道自己站在哪。** 链的终点就是读者眼前的这一页，页面上没有任何地方说这件事。

约束（同时成立，无一条可让步）：数据面零外部请求；**不新增依赖**（不引 3D / 图表 / 动画库）；
视觉语言「档案标本」——1px 细线、等宽编号、纸墨色 + 单一琥珀信号色，**禁止圆角卡片堆叠、渐变霓虹、投影**；
CJK 字体字符集**零余量**（新汉字若不在现有分片 `unicode-range` 内会让 `verify:cjk-fonts` 失败，
补救要外网重裁字体）；首页目录的编号必须连续（新页只能排在 08）。

## Decision

页面是「项目架构」（`/architecture`），入口放在页脚的「数据说明」旁边，并登记为首页目录的第 08 项
（`nav:false`：站头导航入口数受 ADR 0004 约束，不加第 7 个）。这一页有两张图：本记录只管**链路那张**
（等距台阶），楼体剖面那张见 [0026](./0026-architecture-page-as-isometric-section.md)。

**图的语言：手绘等距台阶。** 六级台阶沿 30° 等距轴下降，一级一层；顶层（外部源）画成**线框无填充**，
表示不属本站、只读；其余五级是实心台阶。每一级的前沿嵌一条琥珀流线，从上一级经垂直落差落到下一级；
各级台阶上立着一排小牌，牌数 = 该层在台账里记的节点数。立体感**只靠三档中性面色**（顶面 `bg-3`、正面
`bg-0/bg-2` 混、侧面更暗）与 1px 描边表达，没有投影、没有渐变。

**几何是纯函数算出来的，不是画死的。** `src/utils/isoStage.ts` 按容器宽度反解台阶尺寸、牌位、流线折点、
标注引线端点与画布高度（`layoutStair`），窄屏另有 `miniSlab`。三维投影只有一句 `(u−v)·cos30, (u+v)·sin30 − h`。
没有 3D 库、没有 canvas、没有 WebGL：一张 SVG 画几何，**文字用 HTML 绝对定位覆盖在上面**
（`components/iso/PipelineStair.vue`）。这样文字保持直立、可选中、可聚焦、可被读屏读出，也随字号缩放而不失真。

**交互只做四件事**（都不打断阅读）：悬停/聚焦/点击一级 → 该级抬 3px、描边转琥珀、引线转琥珀、
读数珠跳到该级；「走一遍」按序遍历六层；入场时六级按 70ms 错峰落位、琥珀流线自绘；全部在
`prefers-reduced-motion: reduce` 下退化为静态（三条规则显式写在组件样式里，不依赖全局降速）。

**窄屏换一个装置，不压缩那张图。** <900px 用 `components/iso/IsoColumn.vue`：同一种等距小台阶逐行竖排，
左侧一条琥珀竖线把它们串起来，文字在右。此时不渲染宽屏 SVG（`v-if` 按 `useMediaQuery` 切换，
DOM 里不存在第二份内容）。

**事实单一事实源 = `src/domain/pipeline.ts`。** 六层的编号、中英名、一句说明、交接动词、节点清单、
落点、附注全在这一份；图与台账都按它渲染。图上的读数（数据版本、快照日期、收录条目、展示语言）
全部运行时动态取（`useDataVersion` / `listFor` / `LANGS`），**一个数字都不写死**。

**图下必须有台账（六行）与「图上省去的几处」。** 台账给出每层的节点、落点与附注；第二个区块
明确写出图上省略的三件事——反向的版本对账、门禁的真实位置、字体子集先于门禁的顺序。图上画的是
简化，简化必须在同一页被点明。

## Alternatives considered

- **引 Three.js / 任何 3D 库。** 能给真立体与光照，但违反「不擅自加依赖」，且光照/投影本身就是
  设计语言明令禁止的东西；渲染出来的文字还要自己排版。否决。
- **CSS 3D（`transform: rotateX/rotateZ` 转平面 + 反旋转文字）。** 不引库就能「真 3D」，但文字反旋转后
  与平面的交点难对齐、命中区域随透视变形、引线端点要靠额外计算猜，抗锯齿在 Retina 上也不稳。否决。
- **纯流程图（水平方块 + 箭头 + 说明列）。** 最省事、最稳妥，但表达不了「落到本地」的纵深，
  而且站内已经有账册/表格那套横向排布，再画一张横排方框图只是换了个形状的清单。否决。
- **把 `/about` 的四段文字步骤图化。** 省事，但那四段是按「定时任务脚本」切的，不是按真实边界切的
  （门禁在自动任务里、字体子集在门禁之前、运行时才是读者所在）。照它画会把已经澄清的事实画回模糊。否决。
- **canvas / WebGL 绘制。** 文字要自己逐个画、不可选中、不可聚焦，打印与读屏都无解。否决。
- **把图并进 `/about`（不新增路由）。** 页脚入口只有一行位置，且 `/about` 是中文长文页：
  一张可交互的图会打断长文的阅读节奏，也让「长文页只读」这条既有约定变复杂。否决。
- **窄屏把宽屏那张图等比缩小。** 1000 单位的图缩到 390px，正文标注约 5px——不可读。否决。

## Consequences

- 代价：多一个懒加载 chunk（不进首屏主包）；多一处「结构事实」要跟真实管线同步——以后改 sync 的
  阶段或门的归属，必须同步 `domain/pipeline.ts` 的 `nodes` / `where` / `note`，否则图上就是错的；
  等距几何在换宽度时重算（ResizeObserver），窗口连续拖动会有一次重排。
- 收益：一条链能一眼读完，也能逐层核对到文件与命令；窄屏有等价且可读的表达；零新依赖、
  零外部请求；页脚与首页目录各多一个入口，读者知道链的终点就是自己正在读的页面。
- 遗留缺口：图是**简化**——门禁的判据细节、图标/立绘的派生图分支、离线缓存的淘汰策略都只落到
  一层台阶里，没有各自的节点；hero / art / gif 等派生目录是否回源同一 CDN 未逐一核实，
  故图上一律写「素材图库」而不点名具体目录。
- 陷阱（等距图带来的）：SVG 里的 `<text>` 不能用来承载**信息**（缩放与字号不可控、复制不了），
  故台阶号是纯装饰（`aria-hidden` 的 SVG 内），真实的层号与名称在 HTML 标注里各有一份；
  两处必须同时改（`isoStage.ts` 只给坐标，编号来自 `domain/pipeline.ts`）。
