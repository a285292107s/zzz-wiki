# 决策记录 0021：详情页索引列宽度随语言自适应

Status: implemented
Class: bug-fix

## Problem

宽屏左侧索引列（`base.css` 的 `.section-nav`）宽度写死 96px，标签行单行省略。96px 里编号约 13px、
间距 10px，标签只剩 72px ≈ 9 个等宽字符：中文四字标题放得下，换成英/日/韩就成批截断。1440 视口实测
英文 7 条被截（最长 `Character introduction` 需 169px）、日文 4 条（`ロープネットの印象` 需 118px）、
韩文 1 条（`마인드 스케이프` 需 92px）。裁切是「合法」的局部省略，文档级横向溢出仍为 0，
`verify:ui` 与既有审计都看不见，只有用非中文语言打开页面才会暴露。

同时左侧留白还有 86px 是空的（1440 下侧栏右缘 x=123、正文左缘 x=209）：不是没空间，是宽度写死。

## Decision

- `.section-nav` 宽 `max-content`，`min-width: 96px`、`max-width: 152px`：由当前语言的标签自然宽度决定，
  中文维持 96px，英/日/韩实测分别落在 152 / 142 / 116px。
- 标签行改为两列网格（编号列 `auto` + 标签列 `1fr`），允许折行并 `overflow-wrap: break-word`；
  折行时第二行对齐到标签起点（悬挂缩进）。不再用省略号，也不再依赖 `title` 才能读全名。
- `max-width: 152px` 与 1400 断点、30px 呼吸是同一笔账：1440 视口下栏左缘到正文左缘 182px，
  152px 用完还剩 30px；改这个上限要同时看余量，超过约 182px 会压住正文。
- 窄屏吸顶横条（`max-width: 1400px`）恢复 `display: flex` 与单行不换行，行为不变。

## Alternatives considered

- **固定宽度改成 176/192px**：1440 下压到正文；要不压只能把侧栏断点提到约 1560，让 1440/1536 笔记本
  失去侧栏。
- **提高侧栏断点，1400–1560 改走吸顶横条**：零截断，但白丢侧栏，横条要滑着看，比两行更差。
- **导航另立短标签**（`Character introduction` → `Intro`）：英文可全单行，但要动四份
  `uiText.*.json` 与类型，且导航词与区块标题不再一致、四语各养两套词。暂不做。
- **hover / 浮层展开**：目录本应一眼扫完，多一步交互，键盘与触屏都不友好。
- **缩字号 / 字距**：最长一条要 169px，缩到放得下会破坏 11px 等宽字号体系，只是把问题推迟。

## Consequences

- 收益：四语侧栏零截断；中文栏宽与位置不变（96px、x=27）；英文只剩 3 条折成两行，日/韩全单行。
- 代价：英文侧栏高度 390 → 424px；极矮视口更接近上下溢出（现状已接近，未新增布局约束）；
  `/formulas` 与详情页共用 `.section-nav`，其中文标签可能把栏宽从 96 撑到 100 出头，需同屏确认。
- 可观测：任何语言下 `.sn-item > span:last-child` 的 `scrollWidth === clientWidth`。
- 遗留缺口：`scripts/audits/section-nav.js` 只覆盖窄屏横条，桌面侧栏的「标签被裁」没有断言；
  补一条 `scrollWidth ≤ clientWidth` 的正向断言即可把这类回归钉住。
