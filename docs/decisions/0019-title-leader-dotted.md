# 决策记录 0019：标题右侧的修饰线用点线引导，不用实线或虚线

Status: implemented
Class: feature

## Problem

0017 删掉标题右侧的延伸线后，区块头只剩「编号 + 标题 …… 英文注记」两端对齐：中间 700–800px 的空档
把标题和它的英文注记（CORE / SKILLS / VITALS…）拆成两个孤岛，读不出后者是前者的附注。需要一条修饰线
把它们连起来。但这条线不能再变回"边界线"——区块之间的边界已交给空隙中线上的金色刻线（0018）；它只是
标题行内部的**引导件**，画法有实线 / 虚线 / 点线三种候选。

站内已有两套断线语法，选型必须服从它们：

- 点线 = 引导线（`.leader`：音擎名录卡、数据说明页把名称与数值连起来，`border-bottom: 1px dotted
  color-mix(in srgb, var(--ink-2) 72%, transparent)`）；
- 虚线 = 缺失 / 占位（富文本键位图标缺失时的虚线方框 `border: 1px dashed var(--line-1)`、`HollowImage`
  的兜底框）；
- 连续实线 = 内容结构（表格底边、盒边、行分隔、内容胶囊上下缘）。

## Decision

- `.section-head .leader`：`flex: 1; height: 1px; border-bottom: 1px dotted
  color-mix(in srgb, var(--ink-2) 72%, transparent)` —— 标题与右端英文注记之间一条点线引导，落在文字
  基线上，长度吃满两者之间。
- 纯装饰：`aria-hidden="true"`，不进无障碍树；三处渲染（`DetailSection`、首页「今日角色」「目录」两处
  `section-head`），骨架 `DetailSkeleton` 的头行同步补一条点线占位。
- 颜色复用 `--ink-2` 72%（与 `.leader` 族一致），不引入新 token。
- 审计：`composition-audit` 的 `headRule` 判据增加一组 —— 有 `.en` 的头部必须有 `.leader`，且其
  下边线为 `dotted`（把选型钉在门禁里，防止被随手改成实线/虚线）。

## Alternatives considered

- **实线**（把 0017 删掉的延伸线原样加回）：790px 连续实线重新把头部读成"一条横线"，与「连续实线只属于
  内容结构」的口径冲突，也会和区块之间的金色刻线抢注意力；在同一张头部截图里，实线的视觉重量比点线高
  一个层级。
- **虚线（dashed）**：站内虚线已经被"缺失 / 占位"占用，用它连接标题会读出"这里缺东西"的歧义；且 dashed
  的划长/间隔由浏览器固定、不可控，节奏偏机械。
- **保持两端对齐、不画线**（0017 后的状态）：英文注记成孤岛，标题行右侧的大空档没有依附物。

## Consequences

- 收益：标题与英文注记重新成为一个「引导 → 落点」单元；点线的断口自动降权，不与金色刻线、内容实线竞争；
  与站内 `.leader` 引导线同族，跨页一致。
- 代价：头部又多了个装饰元素；1px 点线在低亮度屏幕上偏细（`--ink-2` 72%），可能弱到只剩一条灰带 —— 但比
  实线/虚线的语义歧义更可接受。
- 遗留缺口：骨架的占位线用 `--line-1` 点线（加载态示意，不追求同色）；首页与详情页共用同一条规则，若未来
  某个头部要单独定制需要覆盖 `.leader`。
