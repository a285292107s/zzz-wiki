# 决策记录 0016：左右翻转作为取景的可选第五项，按画幅存、只镜像成品

Status: implemented
Class: feature

## Problem

官方的 Mindscape 母版每张朝向不同，而站点把同一张图放进朝向要求不同的展示格：详情页桌面 hero 是
2.8:1 满栏横幅、文字浮在左半，角色朝画面内侧（右半朝左）更顺；竖卡与移动端头图则应以官方原画的
朝向为准。此前取景只有平移/缩放四件套，遇到「角色朝向与版式相反」时只能换图或接受别扭的构图。

## Decision

**`flipH` 是每个画幅的可选布尔，缺省即不翻转；渲染上是「取景先照旧、成品再镜像」，不是镜像源图再取景。**

- 参数位置：`calibrated[id].modes[mode]` 里与 `pos` / `posY` / `zoom` / `originY` 并列，可缺省；
  只有 `true` 才落盘（不写 `false`）。契约在 `src/domain/featuredPool.ts`。
- 渲染：`transform` 统一由 `src/utils/cameraRect.ts` 的 `framingTransform(f)` 生成，即
  `scale(zoom) scaleX(flipH ? -1 : 1)`，`transform-origin` 的 X 恒 50%。两个 transform 函数等长是硬要求：
  首页牌堆起飞前变形在 `transform` 上过渡，函数列表同构才按 `scale` / `scaleX` 逐项插值；矩阵插值会退化成
  旋转/压扁。
- 取景不变：四件套的含义与数值都不因翻转改变，翻转只镜像最终可见画面——既有校准打开翻转不必重算。
- 工具所见即所得：`/calibrate` 翻转开启时全景图与取景框一起镜像显示，拖框方向同步镜像（`cx` 换算回源图
  坐标再交给 `framingFromRect`）；成品预览与网格缩略图显示镜像后的成品。
- 派生：未显式校准的画幅从 9:16 母版派生时继承母版的 `flipH`；「按 9:16 母版重派生」同样以母版为准。
- 首页精选池：`pool` 条目随 `modes['9:16'].flipH` 派生同一标记，`FeaturedCard` 透传；牌堆常态取景与详情
  hero 目的地取景各用自己画幅的翻转。
- 审计：`hero-flight` 读 `matrix()` 首分量当 scale 的地方取绝对值——翻转后矩阵为负，否则翻转卡会被误判成
  「没变形」。

## Alternatives considered

- **按角色全局一个开关**（`calibrated[id].flipH`）：省一次点击，但把同一张图在竖卡与 hero 上的朝向绑死。
  画廊要保留官方朝向、横幅又需要朝内时两种诉求互相牵制；反过来若因此全部不翻，hero 的版式收益就没了。
- **镜像源图再取景**：画面几何与「成品镜像」等价，但等价关系要求把 `pos` 换算成 `1 - pos`，即所有既有校准
  数据打开翻转时全部反向重算，工具里 `pos` 的方向感也与页面相反。
- **翻转只在工具预览里做、页面不生效**：校准的意义是「校准所见即页面所见」，不成立。
- **不落盘、运行时按版式自动决定朝向**：不可复现，也违背校准表作为唯一事实源。
- **用 `object-position` 反向表达翻转**：只能挪取景窗，改变不了画面内容的左右。

## Consequences

- 代价：校准表多一个可选字段；工具多一个开关与「镜像显示坐标 ↔ 源图坐标」的换算；镜像会改变角色朝向与
  配件左右（不对称配饰、画面文字），官方美术被镜像本身需要作者逐张目检、确认展示上可接受。
- 代价：卡片与 hero 翻转不一致时，起飞前那 300ms 变形会看到一次翻面（`scaleX(-1) ↔ scaleX(1)` 折叠）。
  这是两个画幅各自取向的直接结果，且发生在飞行开始之前，降落端不会露出镜像画面。
- 收益：不改素材、不新增图源即可修正朝向；竖卡与横幅可各自取朝向，一个展示格翻转不牵连其它页面。
- 缺口：`flipH` 缺省即不翻转，只对确实需要的画幅开启（当前 `featured-pool.json` 里已有若干画幅开启）；翻转后若构图
  仍需微调，回到 `/calibrate` 调四件套。
