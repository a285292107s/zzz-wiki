# 决策记录 0029：窄屏导航改成固定底部栏

Status: implemented
Class: architecture

## Problem

≤999 的导航一直是站头右上角的 ☰ + 推开面板（决策 [0004](./0004-single-nav-entrance.md)）。
它解决了「导航入口只留一处」，但形态本身有三个躲不开的代价：

1. **拇指够不到。** 手机竖握时右上角是单手最难到达的角；导航却只有那一个入口。
2. **展开会把正文推下去。** 面板是推开式，站头 sticky，六条细线行一开就顶掉半屏，
   读者点一次导航等于打断一次阅读。
3. **320 档的空间已经见底。** 品牌 219 + 行距 12 + 工具组 70（检索 30 + 菜单 34 + 组距 6）
   = 301 > 内容宽 280，旧版只能靠 ≤359 隐去品牌副标题与装饰 logo 硬挤；
   而这 70px 里真正高频的只有检索。

同时，四个数据类目是站内最高频的目的地，却要经过「点 ☰ → 找条目 → 点」两步；
战斗公式与设置是低频项，和类目混在同一张六项清单里。

## Decision

≤999 由固定底部栏接管导航，站头只留品牌与检索；≥1000 的主排导航不变。

- **底栏 = 4 个数据类目 +「更多」。** 类目直接可点，编号与站头导航同源（01–04）；
  「更多」展开一条贴着底栏上沿的面板，列战斗公式（05）与设置（06）。
  两处都从 `catalog.ts` 的同一份入口清单派生，类目短标签取 `CatalogEntry.tabLabel`（四语，如 en
  `Agents / Engines / Discs / Bangboo`），完整类目名仍留在桌面主排导航；「更多」面板
  按 `GUIDE_ENTRIES` 的全标签列 05 战斗公式 / 06 设置。
- **视觉沿用「档案标本」。** 底栏内容高 56px、顶部 1px 细线、纸底面、零投影、零圆角卡片；
  条目为等宽编号 + 11px 短标签，当前项是琥珀编号 + 顶沿 1px 刻线。「更多」的编号位
  不是字体省略号，而是三枚 2×2px 方点（3px 间距；面板打开时转琥珀、标签提亮，
  但不占当前项的顶沿刻线）。没有图标资产。
- **下滑隐藏、上滑出现。** 向下滚超过 6px 收起，向上滚 / 回到页顶 / 到达页底时出现；
  键盘焦点在栏内（`:focus-visible`）时保持展开；`Tab` 键也能把收起态的底栏叫回来。
  收起时同时加 `inert` 与 `visibility: hidden`，链接退出焦点序与无障碍树。
  回顶按钮共用这份可见性状态：底栏收起时一起淡出，底栏出现时一起淡入；
  它自己被聚焦时保持可见，不让焦点停在一个已隐藏的控件上。
- **「更多」是 disclosure，不是模态。** `aria-expanded` + `aria-controls`，不圈焦点、不加遮罩。
  收起时机：点面板内任意链接（含「当前页自己」）、点底栏外、`Esc`（焦点归还「更多」钮）、
  路由变化、检索面板开启、页面滚动。
- **全局让位。** `--tabbar-h`（56px 内容高）与 `--tabbar-inset`（安全区）是两个分项，
  `--tabbar-offset` 是它们的和：`.shell` 底部留白与回顶按钮的 `bottom` 读这个和，
  底栏自身读两个分项。回顶在底栏收起时随之淡出并落回 12px（`bottom` 与底栏同用
  `--t-med` 过渡，不跳变），在「更多」展开时隐藏；桌面没有底栏，维持原来的显示规则
  （滚过 320px 且未接近页底时出现）。
  打印态底栏移除、两个分项归零。
- **断点只有一个。** 底栏的 `max-width: 999px` 与站头主排导航的 `min-width: 1000px`、
  详情页动作行的 `<1000` 同值；改任一侧都要同改其余两侧。
- **DOM 顺序按键盘顺序排。** 底栏在 `<main>` 之前（视觉上 fixed 贴底），键盘与读屏
  先于全文到达导航；不要按视觉位置把它挪到页脚之后。

### 空间账（320 基准，四语实测）

| 项 | 宽 |
|---|---|
| 品牌（logo 24 + 间距 10 + 文本 185） | 219 |
| 行距 | 12 |
| 检索（图标形态） | 30 |
| **合计** | **261** |

内容宽 280 → 余 19；品牌副标题与装饰 logo 全档保留（旧版为 ☰ 让位而隐去）。
底栏 5 个等分条目在 320 档每项 56px，四语短标签实测 `scrollWidth - clientWidth = 0`。
四语 × 320/390 文档横向溢出 0。

## Alternatives considered

**保留 ☰ + 推开面板，只把按钮做大。** 否决：右上角够不到的问题不变，推开正文的代价也不变；
把六项全塞进底栏又会在 320 档放不下 en「Drive Discs」、ja「ドライブディスク」。

**底栏直接放全部 6 项。** 否决：320–390 档每项只有约 47–58px，ja/en 的长标签必须缩写或折行；
「更多」把低频的公式/设置收一层，换回四个类目的可读宽度。

**4 类目 + 设置进「更多」、公式常驻（5 + 更多）。** 否决：第五项和四个类目不等宽，
读起来像一个例外；公式与设置都是图文板块，归同一层更整齐。

**图标 + 标签。** 否决：要新增 4–5 枚本地图标资产，且与站内「等宽编号 + 标签」的导航语法断开。

**底栏始终常驻。** 否决：长文阅读时 56px 是纯损失；改用滚动方向控制显隐，
并用「焦点在栏内不收起 / Tab 召回」补上键盘路径。

**「更多」做成模态抽屉（遮罩 + 焦点圈定）。** 否决：它是站内导航，不是需要专注的任务面；
底栏本身已经固定，面板贴在栏上沿即可，遮罩只会多一层。

**检索也移入底栏。** 否决：检索不是导航目的地，混进同一排会让底栏变成 6 项；
顶栏保留图标形态的检索钮，空间账也放得下。

## Consequences

- **代价**：页面底部固定让出 56px（+ 安全区）；底栏收起/出现依赖滚动方向，需要审计守住；
  公式与设置从「一次点击」变成「两次点击」；`useBottomBar` 的模块级可见性状态把底栏与回顶按钮耦合起来。
- **收益**：四个类目单手一次可达；不再推开正文；320 档品牌副标题回归；站头窄屏空间账从 301 → 261；
  导航仍不依赖任何数据请求（拦掉名录 JSON 后底栏与更多面板照常可用）。
- **遗留缺口**：
  - 详情页页头的「返回名录」仍只在窄屏出现，与底栏高亮的当前类目指向同一处；
    这是已知的第二入口，收掉它要另立记录并复核 [0014](./0014-detail-back-link-narrow-only.md) 的空间账。
  - 768–999 的平板也使用底栏（与站头 ☰ 同一断点）；在宽平板上五个条目会拉得很开，
    是否给平板单独保留主排导航，需真实设备复核后再定。
  - 底栏按 4 个数据类目定宽；新增类目会让 320 档每项低于 56px，需先重算空间账
    （或把多出的类目收进「更多」）。
  - iOS 的 `env(safe-area-inset-bottom)` 需要 `viewport-fit=cover` 才非零；本站未开，
    底栏落在浏览器工具条之上，安全区取 0。若将来做全屏 PWA，要同时改 `index.html` 的 viewport。
