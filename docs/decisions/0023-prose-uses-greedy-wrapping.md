# 决策记录 0023：正文改用浏览器默认断行，不再全局 `text-wrap: balance`

Status: implemented
Class: bug-fix

## Problem

站内正文曾统一加 `text-wrap: balance`（`base.css` 的 41 个选择器 + 4 处组件级规则），
目的是消除 CJK 末行只剩 1–2 个字的孤字。`balance` 确实做到了这一点，**且不增加行数**，
代价却是把**每一行**都压短：它按"各行等长"重排，于是两行块变成两条半宽行、三行块的
每行都短两成，同一列表里每一行的右边缘互不相同。读者看到的是"每句话都提前换行"。

1440 宽实测（`/formulas`，行宽 = Range 逐行矩形宽，容器宽取 `clientWidth`）：

| 块 | 容器 | `balance` 逐行宽 | 默认断行逐行宽 |
|---|---|---|---|
| 乘区账目 `dd` | 474 | 247 / 260 | 468 / 39 |
| 段落 `prose` | 583 | 294 / 294 | 560 / 28 |
| 规则 `rule-text` | 531 | 371 / 401 / 378 | 513 / 255 |
| 段落引导 `part-lead` | 624 | 465 / 480 / 480 | 600 / 615 / 210 |

约束：Chrome 的 `text-wrap: pretty` 对 CJK 无效——实测它与默认断行的逐行宽完全一致
（`[574,42] → [574,42]`）。所以当时只能在"孤字"和"每行都短"之间取一个。

## Decision

正文一律使用浏览器默认的贪心断行，即不写 `text-wrap`：

- `base.css` 中那整块 41 个选择器的 `balance` 规则与配套说明已删除；
  组件级同步移除 `FormulasView` 的 `.source-note`、`HomeView` 的 `.desc`、
  `WEngineDetailView` 的 `.story` / `.refine-desc`。
- `balance` 只保留在**标题**上：`.page-title`、`.section-head h2`。标题是单行或两行的
  展示字，等长折行是想要的排面，且不会把整段正文压短。
- 末行 1–3 字的孤行不再交给断行算法回避：出现时按文案处理（缩短句子）或接受。
  它是断行的正常结果，不影响可读性；而"每行都短 20–50%"会直接破坏可读性。

## Alternatives considered

- **保持 `balance`（旧方案）。** 没有孤字、不加行数，但每行短 20–50%，同列右边缘逐行不同，
  已按排版缺陷报告。否决。
- **`text-wrap: pretty`。** 规范上正是"避免孤行"的解，但 Chrome 对 CJK 无实现，
  实测逐行宽与默认断行完全一致。否决。
- **只对列表取消、段落保留 `balance`。** 同一页会出现两种右边缘（列表排满、段落半宽），
  比统一早换行更乱；段落里的短行一样显眼。否决。
- **用脚本计算最优断行（`balance` 的 CJK 版）。** 静态站要在运行时测量每块文本、重排，
  引入布局抖动（CLS）与额外脚本，收益只是几个孤字。否决。

## Consequences

- 代价：孤字回到正文里。实测 `/formulas` 52 个多行块中单字末行 1 个、2–3 字末行 6 个，
  `/about` 16 个块中单字末行 0 个、2–3 字末行 2 个。这类孤字要靠改文案或调 measure 处理。
- 收益：行宽可预测（等于容器宽），同一列表各行的右边缘一致；同时删掉了 41 个选择器的
  全局规则与 4 处组件级规则，断行行为回到浏览器默认，不再需要按"短块"逐类点名。
- 遗留缺口：各块的 measure 仍是 62–68ch 的常量，未做逐块校准；极长段落（> 6 行）在
  `balance` 时代本来就会自动退回默认断行，因此长文与短块的断行差异不再是问题，
  真正的缺口是"没有一个自动的孤字检查"。孤字现由 `composition-audit` **报告基线、不计失败**
  （当前 81 处 / 50 个组合）：它是正常断行的结果，守住它等于重新要求 `balance`，
  要治理只能改文案或调 measure。
