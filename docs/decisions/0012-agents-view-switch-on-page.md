# 决策记录 0012：陈列版本切换移回名录页，两版共用一个页面外壳

Status: implemented
Class: feature

## Problem

`/agents` 的两套陈列（卡片 / 表格）此前各是一整页视图：页头、筛选与检索工具栏、取数、
`AsyncState`、排序配置全部各写一份，两页只在「怎么陈列」上不同。于是任何工具栏层面的
改动都得在两条链路各做一遍，两版的行为也容易在后续维护里漂开。

切换入口在 `/settings`：想换陈列方式，得离开名录页、改完再导航回来（整页重挂载、丢失滚动
位置），而名录页本身没有任何入口或提示——读者默认以为名录只有一种形态。这是设置页里唯一
一项「改完还得到别处才看得见结果」的偏好。

同一轮里还确认了卡片格的退化兜底没有价值：立绘缺失时垫一枚名录图标（与表格版同一枚
`IconRole*` 横幅图，约 179×64）。立绘与图标现在都存在本地，不存在「图标在、立绘缺」的资产
组合；何况真缺一张立绘时，在 9:16 格里垫一条横幅图比留空底更违和。这条兜底还让每张卡先请求
`img/character/thumb/`——该目录从未生成，62 张卡必然各吃一次 404。

## Decision

**`/agents` 是一个页面（`src/views/AgentsView.vue`），页面内按本机偏好择一渲染两个陈列体；
切换钮就在名录页工具栏。偏好仍是本地偏好、不进 URL。**

- `AgentsView.vue` 负责页头、筛选/检索工具栏、取数与排序，陈列体有两支（都静态 import，
  合并进同一个 `/agents` chunk）：
  - `src/components/list/AgentCardList.vue`：卡片陈列 + 渐进加载（首屏 18 条，
    `rootMargin: 400px` 自动续载；无 `IntersectionObserver` 时退化为「显示更多」按钮）；
  - `src/components/list/AgentTableList.vue`：表格陈列（列配置 + 单元格插槽）。
  切换陈列只换陈列体，不重新取数（数据在页面壳里）、不导航、地址栏不变；筛选/检索/排序
  状态本来就在页面壳里，切换后原样保留。
- 切换钮在工具栏右组（检索框左侧）：`role="group"` + 两颗 `aria-pressed` 按钮
  （`uiText.list.viewCards` / `list.viewTable`，组名 `list.viewMode`），选中格琥珀底 + 琥珀字。
  不引入新的控件语言：与筛选触发钮同一套方角、发丝线、字号与字距。
- 偏好单一事实源仍是 `src/composables/useAgentsViewVersion.ts`：模块级 `ref` + 键
  `zzz-wiki:agents-view`，取值 `'cards' | 'table'`，**默认 `'cards'`**；只落 `localStorage`、
  **不进 URL**（决策记录 0008 的核心约束原样保留）。
- **入口唯一**：`/settings` 删掉「代理人列表页版本」选项板，设置页只剩佩洛伊斯立绘形态与
  展示语言两项（后者仍只在设置页，因为站头没有语言控件的宽度空间，见决策记录 0010）。
- `AgentCardGrid.vue` 删掉图标兜底层：取景格里只有一层立绘 `<img>`；立绘候选链耗尽时留
  `--bg-0` 空底（不改版式、不塌高），也不再产生 `character/thumb/` 的 404。
- 旧的外壳与卡片整页视图（`AgentsRouteView.vue` / `AgentsCardsView.vue`）随之删除；
  路由 `/agents` 与逐路由预载（`generate-route-html.mjs` 的 `VIEW_OF`）直接指向 `AgentsView.vue`。

## Alternatives considered

- **保留入口在设置页**（0008 的交付形态）。读者要在两个页面之间往返才能换一次陈列方式，
  且名录页没有任何可见入口；对一项「只影响这一页怎么读」的偏好，这是最远的落点。否决。
- **两处都摆入口**（设置页选项板 + 名录页工具栏）。同一偏好在多处各摆一个入口，必然出现
  「这页切了、那页没变」的错觉——0008 的备选里已用同一判据否掉过「详情页摆形态钮」，
  这里同理。否决。
- **只把入口搬进页内、仍保留两整页视图**。切换钮与工具栏就得在两份视图里各写一遍（正是
  这次要消掉的重复），而且切换会重挂载整页、重新取数、丢滚动。否决。
- **版式写进 URL**（`?view=cards` 或独立路由）。0008 已明确否决：URL 在本站承载「这份视图
  的内容」（筛选、排序、详情参数），版式是读者习惯；写进 URL 会让复制出去的链接替别人改
  界面，并制造两份可索引名录。沿用否决。
- **动态 `import()` 选中版本**。要先读到偏好才知道该下载哪份代码，首屏要么空一档、要么给
  外壳加一层占位；两版共用的模块极多，单独打包等于把共用部分切两半。仍静态导入、同一个
  chunk，沿用 0008 的判据。
- **保留图标兜底、只给立绘 `<img>` 铺底色盖住它**。这只是把一条没有触发场景的退化路径藏起
  来：DOM 与 `character/thumb` 的必然 404 还在，「立绘缺失时该长什么样」的错误假设也还在。
  否决。
- **删掉表格版只留卡片版**。表格版承载卡片版没有的逐列比对与四语名，0008 已记录这是用户
  要求保留的一类用法。否决。

## Consequences

- 代价：页面壳与两个陈列体拆成三个文件，读代码多一层跳转；卡片版的续载进度在切版式时回到
  首屏 18 条（陈列体重挂载），但筛选/检索/滚动位置不受影响。
- 收益：切换在阅览现场完成（不导航、不重取数、不丢筛选）；两版的重复结构收成一处，工具栏
  改动只改一遍；设置页只留下「改完还得去别处看结果」没有意义的那类偏好之外的两项；卡片格
  少一层 DOM、少一次必然 404 的图标请求。
- 遗留缺口：切换行为没有埋点，无法回答「多少人在用表格版」；跨标签页改偏好不会同步
  （模块级 `ref` 只在模块加载时读一次存储）。
