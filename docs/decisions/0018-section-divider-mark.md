# 决策记录 0018：区块分隔改为空隙中线上的金色短刻线

Status: implemented
Class: simplification

## Problem

0017 之后，区块之间仍由「区块头的上边线」承担分隔：它是 `.section-head` 的 `border-top`，
永远贴在标题上方 14px，而离上一区块的内容有 107px。于是这条线读起来是标题的上划线，不是
两个区块之间的边界（"这条线属于哪个区块"一直读不清）；同时它是一条全宽灰线，遇到上一区块
本身以全宽线收尾（属性表底、档案盒底、影画末行、皮肤画框）时，两条平行的全宽线只能靠拉大
间距来避免成对。

## Decision

- `.section-head` 去掉 `border-top` 与 `padding-top`：区块头本身不再画任何线。
- 区块之间的分隔改由 `.section-head::before` 承担：一条 **短线、水平居中、金色、两端渐隐** 的
  1px 刻线（宽 `clamp(44px, 5.5vw, 80px)`，`--amber` 取 60% 不透明度，`mask-image` 线性渐变淡出两端）。
- 刻线亮度必须低于正文：它是装饰性的章节信号，实色金（对纸底 8.5:1）会比标题/正文先被看到，读起来
  像"页面里最显眼的东西"。取 60% 后合成约 3.7:1（正文 4.5:1），扫读仍先落到标题上；长度也只到
  80px（1440），不再是一条短横线。
- 位置：`top: calc(var(--space-section) / -2)` —— 落在上一区块内容与区块头之间空隙的中线。
  空隙同轮由 `--pad-section × 1.4` 收到 ×1.3（1440 下 121 → 112px）：刻线压暗后空场跟着收一档，
  边界读起来更紧凑，刻线不再独自漂在大片空场的正中。
  首页「今日角色」之上的空隙来自 hero 的 `--pad-section`，该处偏移在 `HomeView.vue` 覆写为
  `calc(var(--pad-section) / -2)`。
- 装饰线用伪元素实现：不占版式流、不进无障碍树、不携带结构语义；骨架（`DetailSkeleton`）同步
  去掉头行的上边线。
- 高对比度模式：刻线换 `CanvasText` 并去掉渐隐蒙版（否则两端连同结构一起消失）。
- 打印态：半透明落纸会淡到丢失，print 块恢复实色 `--amber`（纸上深琥珀）。
- 审计随语法更新：`composition-audit` 的 `headRule` 判据改为「区块头无 `border-top` + 刻线存在、
  薄、短线、水平居中，且一个 `.section-head` 都没扫到时判失败」；`forced-colors` 的检查改读
  `::before` 的颜色与蒙版。

## Alternatives considered

- **独立全宽线居中**（区块头无线，空隙中线画一条全宽灰线）：无收尾线的边界最干净；但上一区块
  以全宽线收尾时，两条全宽线只隔约 70px，等于把最初「两条线挨得很近」的问题重新引回来。
- **左对齐短刻线**：与标题左轴对齐、更"文档化"；但页面所有元素都在左轴起笔，居中的短刻线才读作
  「两个区块之间的分隔」，左对齐会读成「标题的装饰前缀」。
- **区块头完全无线**（连分隔也不画）：最安静；但长页面上每段开头少了"起笔"，且用户明确要保留
  分隔动作。
- **保留区块头上边线、只把字号/间距调大**：线的归属仍在区块头，标题被压的问题不解决。

## Consequences

- 收益：边界线与标题彻底分离（谁都不再"压在标题上"）；全宽灰线只剩内容自带的收尾线和胶囊边线，
  「线 = 内容结构」的语义统一；短刻线不会与全宽内容线成对，因此不必再靠超大间距救场。
- 代价：多了一个装饰元素与一套渐隐/居中/HCM 处理（伪元素、蒙版、`forced-colors` 覆写）；
  金色短线与「单一强调色只用于可操作/当前/关键数字」的旧口径有张力 —— 这里它承担的是"章节标记"，
  与同为琥珀色的区块编号同属一类信号，故按「章节信号色」放行，其余装饰仍不得用琥珀。代价之二：压到 3.7:1 后，刻线在低亮度屏上可能只剩一条暖灰线，接近背景噪声——这是刻意的取舍，它负责标出章界，不负责被盯着看。
- 遗留缺口：半透明在纸上会淡到丢失，print 块把刻线恢复成实色深琥珀（`--amber` 在 print 里已换成
  深色）；`reduced-motion` 无影响（刻线不参与动效）。
