# 决策记录 0027：项目架构页做成可缩放的系统地图

Status: implemented

Class: feature

## Problem

0025、0026 给「项目架构」页配了两张等距图：一块七层剖面（结构）、一段六级台阶（数据链路）。两张图各自成立，但合起来有三处不够：

1. **图是静物。** 每张图只有六七个可指认的对象，其余信息全在旁边的标注列与台账里；读者想找「取数与图标链在哪、它连到谁」得靠翻台账。
2. **模块数量放不进一张静物图。** 站点真实的模块粒度是三十多个（七组组件、四组 composable、三列核心…），
   一张固定构图的图要么画不下标签，要么把标签叠成一团。
3. **同一页两张同构的立体图**（剖面块 / 台阶）读起来像同一张图放了两遍，页面的重点被摊薄。

第一版据此做成了「六段台子 × 二十四格等大立方体，高度 = 连线数」的矩阵。它解决了「可点、可筛、可缩放」，
但没回答「这张图凭什么这样排」：二十四格等大，读者从图上读不出哪一层重、哪一组代码多，也读不出核心那层
是三件互相引用的同辈——尺寸只编码了一个变量（连线数），编排是均匀的。

## Decision

页面只保留**一张图**：可缩放的分层地图（`components/iso/AtlasMap.vue`），编排按分层架构的实测数据来。

- **数据**：`src/domain/atlas.ts` 是唯一事实源——六层（外部与构建期 / 入口与壳 / 页面 / 展示 / 状态 / 核心）、
  三十四个模块（编号、中英名、层、体量档、路径、一句说明；核心的九个额外带 `cluster`）、五十五条连线
  （`assemble` / `load` / `source` / `build` 四类）。模块与连线的取舍按 `docs/architecture.md` 的实测分层来，
  页内明说「这是一张读法图，不是调用图」。
- **两层尺寸编码，都是量出来的**：
  1. **台子长度 = 这一层的代码体量**（各组块长之和）。于是「核心」最长、「入口与壳」最短，
     一串台子的长度差本身就是分层体量图。
  2. **房子的占地 = 这一组的体量档**（四档：<120 / 120–400 / 400–1200 / >1200 行）。用档不用行数，
     是因为行数每次提交都在漂；四档粗到不会因为改几行就失真。
  3. **楼层数 = 它在图上接的连线数**（`barHeight(degree)`，纯函数、单测守）。所以「界面文案表」只有十七行，
     却和路由表盖得一样高——它是全图最窄的一栋。
- **块画成房子，但不画成写实建筑**：每栋有屋顶面、山墙的明暗分档、等距楼层窗带、底部基座、屋顶女儿墙，
  占地够宽（≥22 单位）的再叠一层退台塔冠并压一道屋脊线——这两笔是「一眼认出是房子」的临界，
  再多的细节（窗格、招牌、屋顶设备）都会在 85% 的初始缩放下糊成噪点。
- **它是一个舞台，不是一张插图**：场景上方压一片琥珀色环境光、受光面各带一道自上而下的白色渐变——这两样是**投影里的光**，
  只在这个三维空间内部成立。选中时窗带点亮、地面浮出脉冲光环、一条铅垂线吊起引线，
  其余部分降为底噪：**读一张图的方式是「点亮一条关系」，不是「读满屏标签」**。
- **悬停只给一枚箭头，不给线**：悬停时楼顶上方浮一枚琥珀三角箭头（轻微上下浮动，`prefers-reduced-motion` 下静止），
  不画竖线、不画横杠。铅垂线是「选中之后去测量」的语气，穿过楼身的竖线会被读成一条数据；
  悬停只是「光标现在指着这一栋」，用箭头指认就够。
- **细节按镜头分层出现**：< 55% 无英文无窗带、55–90% 出英文、≥ 90% 出模块编号并点亮楼层窗带。
  初始 85% 的视图只该看见街区轮廓与中文名；一次性全画上会让整幅图糊成噪点。
- **用「一条具体的路」当入口，而不是用「读图说明」当入口**：图上方三条 journey（打开一个详情页 / 在名录里筛一下 /
  半夜自动更新）各是一串模块 id，选中后按 1→N 编号、点亮链上连线、把镜头框到这条链。理由：三十四个模块一次性摊开时，
  新读者没有动机先读图例；但「点开一个角色时发生了什么」是他已经有的具体经验，从那里进图最快。
  代价是 journey 与 `ATLAS_EDGES` 必须保持一致（相邻两格之间真有连线），否则编号会停在一条不存在的路上——
  `tests/iso-atlas.test.ts` 里有一条单测守着这件事（相邻两站必须在 `ATLAS_EDGES` 里连得上），
  加 journey 时写错会当场红。
- **文案分三处，各说一件事**：页头说这张图要证明的结论（站外三块在构建期同步成「本地产物」，运行时只读本地）；
  面板说尺寸与交互口径；图注说「尺寸是量出来的」与「读法图不是调用图」。同一句话不写两遍——上一版把六层与
  长短高矮在页头、总览、读图、图注里各讲一遍，读者读到第三遍时已经不想读了。
- **入口只留一处：首页「目录」的第 07 行**（编号排在数据类目之后、注脚之前），标签与说明取 `GUIDE_ENTRIES`。
  页脚本是台账（数据源 / 版本 / 日期 / 版权），不是目录：曾在那儿并列两条（项目架构 / 数据说明）、后来还长成
  一条带说明的「本站」索引带，两版都删了——页脚一旦变成目录，最下面一屏就多出一个与正文无关的层级，
  而首页目录本来就是站点的索引，一处足够。
- **面板是控制台，不是小作文**：地图下方一条三列——「读图」（宽 / 高 / 台 / 线 / 操作五条口径）、
  「连着最多的」（前六名，按连线数排、带条，点一行就选中那栋楼）、「层分布」（六层计数，点一层过滤）。
  它回答读者看完图最想问的两件事：「这些大小是什么意思」与「所以哪个最核心」。原先的第一列
  「架构总览」（模块数 + 一段六层说明）删了：数字挪进图题右端的规格位（`6 层 · 34 模块 · 55 连线 · 4 类关系`，
  紧挨 `LIVE`），那段说明与页头、图注重复。规格位在地图上方而不是页头下方——读者要的是「这张图有多大」，
  不是「这个站有多少页」。
- **核心那层画成三列，不是三级**：`domain` / `data` / `utils` 在实测里互相引用（契约引用取数层的类型，
  取数层又反过来用契约层的枚举），摞成上下三级会编出一个不存在的层级。物理上做成同一块台子上的三段
  「列架」：列与列之间留双倍缝、栏板各自断开，模块按 `cluster` 顺序排列。
- **两级标签分两处放**：房子名刻在台子前沿的刻字带里（比台面深一档），配一条极淡的引线回指屋基；
  **层名做成一插在台面上的旗**（杆基落在台面左端的刻字带上、杆顶挂一面朝左飞的燕尾旗）。层名比房子名高一级，
  塞进台面里会把整条楼梯读糊——实测塞进台面后，六个层名每个都与一栋房子名相接。做成旗之后重叠归零，
  代价是左侧让出约 150 单位的旗面区、初始缩放从 83% 降到 72%。
  旗比纯文字贵在一件事上：**杆是竖的**。六个杆顶连成一条斜线，与楼梯同向；读者不需要先找到标签属于谁，
  杆脚那个小锚点就指在台子上。杆脚**压一枚等距小旗座**：只留一个小圆点时，初始缩放下根本找不到杆脚落在哪块台子上。
- **地面是一块跟着台子走的地板**：最低那层的底面以下铺一块等距地板，轮廓按台子的阶梯走（每层只比自己的台子宽
  8 单位、前缘再伸出 48 单位当檐），所以它既不戳出多余的大三角，也不会在台子旁边露出一条莫名其妙的边。
  地板只靠一道由后向前变亮的线性光、前沿一道 12 单位厚的基座立面、以及立面上沿那条压了三成琥珀的「台口线」成立
  ——**不画网格、不画投影**（网格的否决见下）；立面与台子的立面同族但更暗，否则读者会把它当成第七级台子。
  它**进包围盒**：`fit` 按宽度收敛，为地面多留的每 10 单位都要从初始缩放里扣；包围盒因此宽了约 63 单位，
  1440 视口下的初始缩放现为 72%。
- **连线画成架空线**：两端切线竖直（三次贝塞尔的两个控制点压在两端楼顶中心正上方，拱高 26–62 单位随跨度收敛），
  于是每条线都像从屋顶接线口引出来的一根架空线：拱顶必然高过两端的屋顶，小跨度上也不会戳出尖顶。
  四类关系沿用颜色 + 粗细（装配细实线 / 读取本地唯一的琥珀实线 / 站外取源更淡 / 构建产出更粗），
  不用虚线——虚线在站内属「缺失 / 占位」语义（见上方 Alternatives）。
  **方向只在点亮时说**：悬停或选中时，这条楼身上的线有光珠从起点流向终点（`stroke-dasharray` + `dashoffset` 动画，
  只有点亮的那几条在动，静止时零动画开销），落点补一枚朝下的小箭头与一枚细环。于是「它调用谁」与「谁调用它」
  不看文字就分得开；而静止时 55 条线一根箭头都不带，不制造噪点。
  **点亮的线浮到所有房子之上**：静止的线在房子下层（等距遮蔽就是这么来的），点亮的线整根搬到最上层，
  不再被中间任何一座楼切断——关系线被切断就失去意义，遮挡的优先级在「点亮」这一态里让位给可读性。
  两层由 `is-lifted` 联动：点亮的线在底层设全透明、只在上层画一遍，避免重影。
- **几何**：`src/utils/isoAtlas.ts` 的 `layoutAtlas` 按固定世界坐标算出六块台面、三条栏板、三十四栋房子
  （每栋含屋顶 / 山墙 / 基座 / 女儿墙 / 楼层窗带，够宽的带塔冠）、五十五条三次贝塞尔投影路径与标签锚点；
  SVG 只画几何（`aria-hidden`），**文字全是 HTML 覆盖层**。
- **交互**：拖拽平移；`Ctrl / ⌘ + 滚轮` 缩放（不劫持普通滚动）；双击放大；右下角「−/+ / 百分比 / 适应」；
  点房子或标签选中（同时点亮它的上下游连线）；悬停高亮；图例四类可逐类关掉；搜索框按名称/路径/说明过滤并压暗其余；
  「层分布」可以按层过滤。
- **面板**：默认是总览（统计、读图、分布），选中后切成该模块的路径与上下游（核心的模块还会标出它在哪一列）；
  窄屏不画地图，改成一列六层清单，点一行在行内展开同样的详情（`AtlasDetail.vue` 两处复用）。
- **窄屏不缩图**：<1024px 不渲染地图（1000 单位的图缩到 390px，正文标注只剩约 5px），改为可读的清单。
- 0025 / 0026 的两张图连同它们的几何与台账一并删除；本记录取代它们。

## Alternatives considered

- **保留两张静物图，只补台账。** 读者要的是「找模块、看关系」，补台账等于把图当中插图用；而且三十多个模块画不进一张固定构图的图。否决。
- **沿用第一版：六段台子 × 二十四格等大立方体。** 可点可筛，但尺寸只编码连线数、编排靠均匀网格，
  读者读不出层级体量与「核心是三件同辈」。而且等大矩阵会把「展示」那层（一万三千行）和「入口与壳」
  （一百九十行）画成一样重，等于图在说谎。否决（第一版已实际做出来并推翻）。
- **用真实行数当块长。** 最「诚实」，但行数每次提交都在变，图与数据必然漂移；而且行数差 60 倍时长宽比失控。改用四档。
- **静态 SVG（不缩放），靠标签避让。** 三十四个标签在 1000px 宽的画布上必然互相压；缩放是把标签分开的唯一手段。否决。
- **构建期扫描源码自动生成模块图。** 更「真」，但要新增构建脚本 + 生成物入库 + 每次改代码重跑，而且自动聚类出来的模块名对读者不可读；
  站点数据面是「构建期落地、运行时不访问外网」，一张手绘的读法图不违反这条。否决（未来可以做成脚本，但那是另一件事）。
- **引 3D 库（Three.js）或力导向图库。** 违反「不擅自加依赖」；力导向图也不是等距，且节点位置不稳定、不可复现。否决。
- **把地图做成全屏应用（占满视口、隐藏站头站尾）。** 与站内「内容胶囊」的阅读节奏冲突，站尾那份台账也没有落处。否决。
- **用虚线区分四类关系。** 虚线在站内已属「缺失 / 占位」语义（见 DATA_GUIDE §10）；改用颜色 + 粗细区分，图例写明。否决。
- **连线照第一版那样从屋顶直接拉一道二次贝塞尔弧（两端斜着起飞）。** 弧是「贴在空中一根飘带」：小跨度上尖、
  大跨度上会垂到屋顶以下，看不出线是接在屋顶上的，方向也完全不可读。改成两端竖直切线后，每条线都有了一个接线口。否决。
- **给五十五条线统统画箭头（或静态的方向点）。** 静止时那是五十五个噪点，而读者的第一眼只需要「哪里连得最密」；
  方向改成只在点亮时给（光珠 + 落点箭头）。否决。
- **把连线统统画在房子前面，省掉被遮挡的麻烦。** 等距遮蔽是这张图立体感的来源，静止时线画在前层会让远处的
  地台压在近处的墙上。只在「点亮」态才允许浮到前面：那一态里读者要追的是一根线的两端，不是整座城的景深。否决。
- **窄屏也画地图。** 见 Decision：缩到 390px 后标注不可读，且触屏拖拽会吃掉页面滚动。否决。
- **核心那层画成三级台阶。** 看起来更像「分层」，但 `domain ↔ data` 实测是双向的，画成上下级就是假的。改用三列并排。否决。
- **把房子画成写实建筑（窗格、招牌、屋顶设备、外挂楼梯）。** 拟物一旦超过「轮廓 + 塔冠 + 屋脊 + 楼层窗带」就会在
  85% 的初始缩放下糊成噪点。停在「一眼认出是一座楼」这一步。否决更细的做法。
- **让 3D 图也严格遵循平面设计禁令（不画投影、不加渐变、灯光全免）。** 这条对「界面」是对的，对「一张三维地图」是自缚：
  平面的纸墨规则是为了让信息在二维网格里可读，而三维舞台的景深与体积本来就要靠光来给。**边界改画在容器上**——
  舞台内部允许光与体积，舞台之外（面板、列表、正文、页脚）保持零投影、零渐变的纸面规则。写清这条边界，
  比让每一处都遵守同一条禁令更省事，也不会让地图看起来像一块贴错地方的平面海报。
- **在图下单独开一个「图上省去的几处」区块（五条注记）。** 做过，然后删了：五条里只有「读法图不是调用图」是读者
  需要的；其余四条（核心为什么三列、门禁不在同步脚本里、构建期产物去哪了、尺寸怎么量）要么是读图口径、
  要么是工程脚注，该去的地方是面板、页头与仓库文档。为一条注意单开一个带编号的区块，视觉分量与内容完全不成比例。
  现在它压成图注末尾的一句话，紧贴地图——误读恰恰发生在那里，而不是在页面底部。否决。
- **把地图的入口做成首页独立的一条带（缩略图 + 一句进入），或塞进站头主导航。** 前者把「一张可以点进去
  玩的地图」压成需要滚动才看到的宣传位，还得在首页另开一节；后者把「本站怎么搭的」与四个游戏数据类目
  并列，主导航的层级就假了。否决：入口的分量靠**说明**（一句话讲清里面有什么）挣，不靠位置与尺寸。
- **给房子加落影来强化体积。** 落影会把地台的层序和引线一起糊掉，而这个场景的体积已经由等距投影、
  受光渐变和楼层窗带给足。否决；允许的是**墙面自身上暗下亮的受光渐变**，不是投到背景上的影子。
- **给整座模型补一块方正的场地大板。** 方板在等距投影里的远角会戳到画面右外侧：包围盒一宽，初始缩放直接掉到
  59%，而那块空板本身没有任何信息。改成跟着阶梯走的地板（见 Decision）。否决。
- **给每层台子各加一圈更大的基座。** 六圈基座会多出六道与楼层同向的边，读者开始数不清哪一级是「层」、哪一级是
  「基座」——而这张图的第一信息就是「六层」。地面只做一层，且只垫在最低那一层下面。否决。
- **在地台下方铺一层等距网格当地面参考。** 做过，然后删了：一层浅灰网格在没有地平线的深色底上抢不掉注意力，
  却让六块台子读成"浮在坐标纸上"而不是一栋建筑；而且它把台基的层序（每层比上层更低一档）压成了同一平面。
  现在地面完全留空，只靠台基的层高差与投影方向交代空间——**少一件东西反而更立体**。否决。

## Consequences

- 代价：多一套地图组件与几何（`AtlasMap` / `AtlasDetail` / `isoAtlas`，约 1100 行），以及一份需要人守的模块数据；
  手绘地图天然落后于代码——改了分层、体量档或主要依赖，要回来同步 `domain/atlas.ts`，否则图会说谎（页内已注明它是读法图）。
- 收益：三十四栋在一屏里可数、可点、可筛；**台子长度差本身就是分层体量图**，房子的占地与楼层数各自编码一件事；
  关系线不再靠文字描述；缩放后标签带英文，细节按需展开；仍是零依赖、零外部请求、纸墨配色（无霓虹、无渐变、无投影）。
- 遗留缺口：连线只画主要依赖，**实测的 import 条数与已登记回跳没有画**（图注里点名「读法图不是调用图」）；
  构建期静态产物（社交卡片、站点地图）与站点地图的 308 归一不在图上；地图没有提供「把当前视图分享出去」的 URL 参数
  （选择与缩放是临时状态，刷新即回全图）；体量档是手填的四档，与实测行数之间没有自动校验。
- 陷阱（地图带来的）：
  1. **标签位置不能只按几何放**——HTML 标签的盒高按世界坐标算，缩放时随之变化；`AtlasMap` 有一道按世界坐标做的避让
     （估计宽高 + 两条候选车道 + 横向平移），改了标签字号必须同步那几处估计值（`zh.length * 12 + 8`、`17`，
     以及放大后多出一行英文时的 `30` 与 EN 宽度），否则会重新叠字。放大到 ≥90% 会多出一行英文、
     车道间距要跟着放大，实测 132% 时仍有约 3 对标签相互贴合（引线还能追回块），属已知取舍。
  2. **地图容器吞掉触摸手势**（`touch-action: none` 才有拖拽），所以窄屏必须彻底不渲染地图，否则页面滚不动。
     同一件事还有另一半：容器必须同时挂 `user-select: none`，否则在按住拖动的这几百毫秒里，浏览器会一边平移
     一边按文本选择跑马灯，松手时满图标签停在反白的选中态——这不是「看起来像」，是真的选中了。
     **`user-select` 只挂在地图容器上**：标签与房子是内容，选中就失去可复制性；右侧详情面板绝不能被它波及。
  3. **手柄按钮与拖拽共用一个指针**：点击判定要区分「拖了多远」，否则每次轻微抖动都会被当成点击。
  4. **层高受台距限制**：房子立在前方台子的刻字带后面，盖得太高会盖住后一排的字。`BAR_MAX_HEIGHT` /
     `STEP_H` / `FLOOR_HEIGHT` 是一组联动常量，调其中一个都要重看图，别只看单个房子。
  5. **改 `src/**` 里的中文会动字体子集**（`verify:cjk-fonts` 零容差）：要么先跑一次
     `node scripts/verify-cjk-fonts.mjs` 再决定措辞，要么准备联网重裁子集。另外**别用 PowerShell 的
     `Set-Content` 改这些文件**——它会写 CRLF，而 `\r` 会被 `collectCharset()` 当成字符收进站点字符集，
     字体门禁于是报「缺口 1 个（示例 空）」：那不是缺字，是行尾符混进了扫描面。
  6. **连线分两层画**：静止的线在 `<g class="cubes">` 之前（等距遮蔽靠绘制顺序给出）；点亮的线
     （`.wires`）与落点箭头、环（`.arrivals`）在 cubes 之后——照亮的关系必须盖过一切房子，否则中间
     任何一座楼都会把线切断。两层由 `is-lifted` 联动（点亮的线在底层 `opacity: 0`，只在上层画一遍，
     否则重影会让点亮的线比别的亮一档）。上层这两个分组必须 `pointer-events: none`：
     `opacity: 0` 不改变命中测试，而上层的线与落点标记正好压在屋顶中心，会抢走房子的 `pointerenter`，
     悬停于是来回闪。
