# 决策记录 0004：导航入口全站只留一处

Status: implemented
Class: architecture

## Problem

窄屏吸顶栏放不下主排导航（4 个数据类目 + 档案图谱 / 战斗公式共 6 项，实测单行需 583px）。
2026-10 的改动把导航从 ☰ 菜单移到**检索面板空态的「直达」区**，站头只留品牌与检索钮，
理由是「少一个按钮、少一份重复清单」。

但这个安排在三处可实测的条件下不成立：

1. **面板高度封顶后导航被推到折叠线以下。** 面板高度取 `min(560px, 100vh − 140px)`，
   而 ≤640 视口另有 `100vh − 120px` 的覆盖——即**越窄反而越高**（390 档实测 724px），
   **641–979 才落进 560px 封顶**（实测 560px、列表区 473px）。而「最近访问」区最多 6 条、
   高 387px，正好把导航推到折叠线以下：641–979 视口下直达区**只有 1/6 项可见**，
   其余 5 项要滚动。而最近访问是 localStorage 累积的——
   **越常用的用户越难到达导航**，方向与预期相反。
2. **键盘到不了。** 打开面板焦点锁定在输入框，Tab 两次才到第一个直达项，↑↓ 完全不在其序列里
   （`move()` 只覆盖最近访问与检索结果）。
3. **索引构建失败即失去全部导航。** 检索面板的可用性依赖四份名录 JSON 构建搜索索引；
   任一份失败时 `useQuickSearch` 把状态退回 `closed`，面板打不开。实测拦掉一份名录 JSON：
   窄屏可见导航项 **0**，且连「战斗公式」「数据说明」这些不参与索引的静态页也进不去。

**桌面这一半是独立的第二个问题。** ≥980 主排导航一直常驻在站头，检索面板却仍列着同一份
6 项清单——同一批目的地在同一屏上有两个入口，只是其中一个藏在 ⌘K 面板里。
提交 `2ca286c` 已在窄屏修过一次这个重复（当时是「菜单 + 面板直达区」并存），
但修复方式是按断点隐藏，于是同一份清单散在三处（主排导航 / ☰ 菜单 / 面板直达区）、
断点还要人工同步——问题是「入口重复」，按宽度切一刀只是让它换个地方复现。

## Decision

**导航入口全站只留一处：站头。** ≥980 是主排导航，≤979 是 ☰ 菜单（断点与主排导航实际所需
宽度对齐）；**检索面板在任何宽度上都不列类目入口**，只做检索。

- `SiteHeader.vue` 的 `.menu-toggle`（≤979 可见）是 disclosure 控件：非模态，焦点不圈定、
  不改 Tab 序；`aria-expanded` + `aria-controls`；按钮名恒为「菜单」（不随开合改名——
  名字随状态变会让读屏听起来像两个不同的按钮）。
- 展开的面板 `.site-menu` 是**推开式**（站头 sticky，展开即把内容下移），逐条细线行，
  与主排导航同列 `NAV_ENTRIES`。收起时机共七条：
  1. **路由变化**（`watch(route.fullPath)`）——覆盖浏览器前进后退与别处触发的跳转；
  2. **点击面板内链接**（面板上的 click 委托，只认 `closest('a')`）——补第 1 条盖不住的
     「点当前页自己那条」（路径不变、watch 不触发）；点面板留白不收起（那是误触不是选择）；
  3. **点击品牌**（`.brand` 上的 `@click`）——品牌在面板之外，前两条都盖不住同页点它；
  4. **Esc**（归还焦点至切换钮，`e.isComposing` 时不拦——那时 Esc 是取消输入法候选）；
  5. **点击站头之外**；
  6. **越过断点转宽屏**（否则展开态残留在 ref 里，转回手机就是「一进来菜单已经开着」）；
  7. **检索面板开启**（`watch(searchPhase)`，而不是塞进站头检索钮的处理函数里）——
     唤起面板有站头按钮与全局 Ctrl/⌘+K 两条路径，后者由 `App.vue` 直接调 `toggle`、
     绕过本组件；只收其中一条会留下「菜单开着 + 模态面板盖在上面」，菜单留在可访问树里、
     指针却点不到，且 Esc 会被站头的文档级监听抢走、把焦点拽出对话框。
- 点击站头之外的判定用「是否落在站头内」，不用「是否点在切换钮上」：后者会让
  `pointerdown` 先关、`click` 再开，等于按了没反应。
- `QuickSearch.vue` **不再列任何类目入口**（`.qs-quick-entries` 与「或直达：」提示整块删除，
  不是按断点隐藏）。理由：导航入口归站头一处——≥980 是主排导航、≤979 是 ☰ 菜单，
  面板再列一遍就是两个入口指同一批目的地（提交 `2ca286c` 修掉的问题）。
  判定「面板不兼任导航」的审计断言写成**断点无关**的：面板内 `<a href>` 数量必须为 0，
  窄屏与桌面各验一次（`keyboard-journey.js` 的 `kb-search-panel-no-nav`）。
- 检索钮在 ≤1100 取图标形态（视觉隐藏文字，非 `display:none`——后者会把按钮文本摘出
  可访问树，触发 axe `button-name` critical）。
- 同批收口两处脚注空头支票（面板已无导航入口后立刻显形）：截断提示 `共 N 条命中…`
  不再于空态出现（空态 `overflow` 按「全部条目」算出 171，而一行都没列）；
  `↑↓ 移动 · ENTER 直达` 只在确有可移动项（`movable > 0`）时给出，
  `ESC 关闭` 常驻。`movable` 与 `move()` 共用同一处算法，不另算一份。

### 空间账（390 基准 · 360 安全下限）

| 项 | 宽 |
|---|---|
| 品牌（logo 24 + 间距 10 + 文本 185） | 219 |
| 工具组（检索 30 + 组内距 6 + 菜单 34） | 70 |
| 行距 | 12 |
| **合计** | **301** |

内容宽 = 视口 − 2×`--pad-page`（4vw，320 档为 20px）：390 档 350 → 余 **49**；
360 档 320 → 余 **19**；320 档 280 → 差 21，故 ≤359 隐去品牌英文副标题（纯装饰），
品牌 219→180，余 17。

主排导航自己的账：219 + 24 + 583 + 24 + 30 = **880**，而内容宽 = 视口 × 0.92，
即视口 ≥ 957 才装得下 → 断点取 979 留约 20px 余量（字体度量在别的机器上会漂）。

## Alternatives considered

**检索面板兼任导航（改动前的现状）。** 否决：上面 Problem 的三条实测——折叠线以下的导航、
到不了的键盘路径、索引失败即全站无导航。前两条是可用性折扣，第三条是**单点故障**。

**保留 720 断点、只在 ≤720 加 ☰。** 否决：721–960 主排导航**本来就放不下**。
逐档实测（每个条目的**标签文字**折几行 / 导航容器高 / 栏外可见溢出；栏高 62px）：

| 视口 | 标签文字 | 容器高 | 栏外可见溢出 |
|---|---|---|---|
| 720–740 | 4 行 | 108.4px | **23.2px** |
| 768–800 | 3 行 | 85.3px | **11.6px** |
| 820–940 | 2 行 | 62.2px | 0.1px（贴边） |
| 950–960 | 1 行 | 39.1px | 0 |
| 961+ | 1 行 | 39.1px | 0 |

`.masthead` 是 `overflow: visible`，溢出文字直接压住页面内容（是**纵向**溢出压内容，
不是横向滚动条——全区间 `docOverflowX` 始终 0）。这是既有缺陷，断点定得比导航实际需要的
宽度低。菜单断点与空间账对齐后，这个区间改由 ☰ 接管——一个改动同时关掉两处。

**菜单钮带文字（「☰ 菜单」，64px）。** 否决：把 390 档的余量吃到 0、320 档直接挤压品牌折行。
桌面断点上「检索」二字本来就已经要收成图标（`≤1100`），窄屏再留一个带字钮没有理由。

**菜单做浮层/模态（带遮罩、焦点圈定）。** 否决：它是站内导航，不是需要专注的任务面；
模态会平白多一层遮罩与焦点陷阱，且站头是 sticky 的，推开式天然不会让内容被挡住。

**保留检索面板的直达区。** 否决，分两步：窄屏先改为按断点隐藏（第一步），
随后**桌面也一并删除**（第二步）——既然导航入口统一归站头（≥980 主排导航 / ≤979 ☰），
面板在任何宽度上再列一遍都是多余的第二个入口。留下的按断点隐藏规则比「整块删除」更差：
它让同一份清单在三处存在、且断点必须人工同步。删除后连带收口两处脚注空头支票（见 Decision）。

## Consequences

- **代价**：站头多一个按钮与约 80 行面板代码；两处断点（979）必须同步，改一处要改另一处
  （已在两侧注释里互相点名）。
- **收益**：**导航入口全站只有一处**（站头），不再有第二个入口随宽度切换形态；
  导航不再依赖搜索索引——名录 JSON 全挂时窄屏仍有完整导航；导航不再受面板高度封顶影响
  （常用用户也能一次看全 6 项）；键盘路径从「Tab 两次 + 无提示」变成「一次 Tab 到切换钮
  → 回车 → 一次 Tab 进第一项」；检索面板回到单一职责，脚注也不再承诺不存在的动作。
- **遗留缺口**：⚠ **721–960 区间的断点变化改变了该区间平板/窄窗用户的导航形态**
  （主排导航 → ☰），尚未在真实设备上复核。
  另：面板展开会把内容下移，若将来给站头加 `position: fixed` 或高 z-index 的横向吸顶条，
  需重新核对层叠关系。
- **已收口（同一改动内）**：删掉类目入口后，面板空态对**新访客**（无「最近访问」）只剩一行
  提示语，等于一个几乎空的面板。现补「检索范围」组（`.qs-scope`，与「最近访问 RECENT」
  同构的组头 + 三行细线）：名称（含外文原名）/ 编号 / 多词空格分隔。两块内容互为替补——
  有最近访问时列最近访问，没有时列检索范围，空查询下面板总有一块内容。
  **内容逐条按实测写**，不写实际搜不到的字段：`domain/search.ts` 头部曾称索引含阵营名，
  实测搜「狡兔屋」「强攻」「代理人」均 0 命中，该注释已订正，说明区也不列这些。
  界面文字用「含外文原名」而非逐语罗列——「韩」字不在已子集化的 CJK 分片里，
  写了会让 `verify:fonts:cjk` 失败（实测；补字需重下重切字体，与本改动不成比例）。
