# 决策记录 0017：区块头只画一条线（删除标题延伸线）

Status: implemented
Class: simplification

## Problem

每个区块头（`.section-head`）画了两条线：上方通栏的开场线（`border-top`），与标题右侧连到英文标签的
延伸线（`.rule`）。两条同为 `--line-1`、平行、相距 38px，长度也接近（1008px vs ~790px）——读起来是同一件事
被画了两遍。

再叠加第三重：上一区块的内容常以一条线收尾（档案详情盒底、属性表底、影画列表末行），这条收尾线离本区块
的开场线只有 76px，同宽、同色。于是同一段边界最多同时出现三条线，读者分不清哪条属于哪个区块（"这条线
属于 02 还是 03？"）。全页账：代理人详情 8 个区块 = 16 条头部装饰线，它们不携带任何数据；内容自带的线
（表格底、盒子边、行分隔）另有 30+ 条。头部这两条是最该瘦身的一批。

## Decision

- `.section-head` 只保留一条横线：上边线。`.rule` 元素与样式从 `DetailSection.vue`、`HomeView.vue`、
  `DetailSkeleton.vue` 删除。
- 英文标签改为标题行的右端注记：`.section-head .en { margin-left: auto }`，靠右对齐与 0.22em 字距收尾，
  不再用线连接；标签词表不变（单词、Title Case）。
- 区块间距 `--space-section` 从 `--pad-section × 0.88` 提到 `× 1.4`：1440 宽 76 → 121px，390 宽 35 → 56px。
  上一区块的收尾线因此不再与本区块开场线成对。
- 档案头 / 详情头底边距（`AgentHead`、`DetailHead`）从 `--pad-section × 0.8` 并入 `--space-section`，
  首屏边界与区块间用同一把尺。
- 审计随语法更新：`composition-audit.js` 的「平行重复线」判据退场，换成「区块头多线 = 0」（`headRule`，
  负向对照：给 `.section-head` 加回一条背景细线即判失败）；`forced-colors.js` 的 `.rule` 检查改读
  `.section-head` 的 `border-top` 颜色。

## Alternatives considered

- **只把间距拉大、两条线都留**（76 → 130px）：双线仍在头部，重复感只靠距离稀释，每屏仍要读两条做同一件事
  的线 → 治标。
- **反过来删开场线、保留延伸线**：头部最轻，但上一区块若以纯文字收尾（角色介绍 → 基础属性、技能招式 →
  核心技），这段边界会一条线都没有；边界线随内容有无而起伏，区块开场也失去与内容无关的固定信号。
- **合并成一条"被标题打断的整行章节线"**（延伸线从内容左缘起笔、编号与标题压在线上）：一条线同时承担
  开场与连接，最接近书籍章节线；但属于新语法，要处理标题压线的断口，且 `.section-head` 是首页与详情页
  共享的语法，改动面与验证成本都更大 → 留作以后可选。
- **只缩短延伸线、或把它降一档墨色**：省改动，但双线结构还在，读者仍会觉得"头部有两条线"。

## Consequences

- 收益：区块头装饰线 2 → 1（详情页 16 → 8 条）；边界的线只由开场线承担，归属不再模糊；英文标签靠对齐与
  字距站住，少一件装饰件。
- 代价：头部少了「标题—标签」的连接件，右端注记更孤立；区块间距放大使页面变高约 5%；首页两处
  `.section-head` 与详情页同步变化（共享语法，故意不分叉）。
- 遗留缺口：`/formulas` 不使用 `.section-head`，不受影响；审计判据换了实现，`QUALITY.md` 与
  `scripts/audits/README.md` 已同轮更新。
