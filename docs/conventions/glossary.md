# 游戏内术语表（手写）

**为什么有这份文件**：`public/data/live/{lang}/noun.json` 是**构建期由源站按语言全量重建的生成物**
（`scripts/build/index.ts` → `dump('live','{lang}/noun.json', …)`），只读、不可写——往里写术语会在下次
`pnpm run sync` 被整体覆盖。所以**本项目自己敲定的术语**落在这里。

| | 本文件 | `noun.json` |
|---|---|---|
| 内容 | 我们自己敲定的术语与**边界** | 源站给的游戏名词 title/desc（四语各一份） |
| 谁写 | 人与 AI，手工 | 构建管线，全自动 |
| 会被覆盖吗 | 不会 | 会（每次重建） |
| 用途 | 统一定义、消歧、给 AI 约束 | 详情页 TermTip 浮层的展示数据 |

**写法**：一个术语＝一句话「它是什么」＋一句边界「它**不**包括什么、与近邻术语的区别」。
定义含糊的说法挂「待澄清」，不要先落一个错的定义。

---

## 1. 四大类目

- **代理人**：可获取、可培养、有等级与突破的战斗角色。**边界**：不含「邦布」（后者是独立类目，
  有自己的名录与技能组），也不含主角绳匠本人。
- **特殊形态**：同一个代理人的另一形态，在名录里是**独立条目、独立 ID**，可独立获取与培养——
  零号·安比（1381）之于 安比（1011）、星徽·比利（1531）之于 比利（1081）。
  **边界**：与**双形态**（同一 ID 的性别变体，如 1551 佩洛伊斯的 Female/Male 头图，见 DATA_GUIDE §5）
  不同——双形态不新增名录条目；特殊形态新增条目，且**与本体同一天生日**（源数据两处都缺
  `partner_info.birthday`，这条事实由 `src/data/birthday-supplement.json` 人工补充）。
- **音擎**：代理人的武器。**边界**：不含驱动盘（后者是 4 件式套装、以「件数」计效果，不是单件武器）。
- **邦布**：随行机偶。**边界**：绳匠专属的 H.D.D. 搭档「伊埃斯（55098）」**不入邦布名录展示**
  （源站是空 icon 的桩数据），由 `BangboosView.vue` 前端策展——所以「邦布名录条数」与
  「邦布可获取型号数」不相等。
- **驱动盘**：4 件式套装。**边界**：效果按「2 件套 / 4 件套」陈述（`desc2`/`desc4`），
  不存在单件效果。

## 2. 属性与分类

- **基础属性（`element`）**：`200 物理 / 201 火 / 202 冰 / 203 电 / 204 风 / 205 以太 / 300 流明`。
  **边界**：`300 流明` 是标准元素，不是「特殊属性」。
- **特殊属性（`special_element`）**：显示层覆盖基础属性的**展示名**，如 星见雅→烈霜、仪玄→玄墨、
  叶瞬光→凛刃。**边界**：它是**展示覆盖**，不是新元素码；构建期由详情 `special_element_type.name`
  注入名录，前端**优先**显示它、无则退回基础属性名。
- **职业（`type`）**：`1 强攻 / 2 击破 / 3 异常 / 4 支援 / 5 防护 / 6 命破 / 7 锋御`。
  **边界**：`7 锋御` 为 v2 新增，源站 ZenlessData 职业表尚未收录——**不要因为上游缺它而"修正"。
- **攻击类型（`hit`）**：`101 斩 / 102 击 / 103 刺`。
- **稀有度**：角色与邦布 `3=A / 4=S`；音擎 `2=B / 3=A / 4=S`。**边界**：两者**不等价**
  （音擎多一个 B 档，角色没有），不要合并成一套。
- **阵营（`camp`）**：源站粗粒度码 `1–17`（如 `16 罗斯凯利法`）；本项目按官方设定把已知角色
  **细分**到下属组织，细分码从 **18** 起（单一事实源 `src/data/camp-supplement.json`，
  由 `domains.ts` 的 `applyCampSupplement()` 注入）。**边界**：细分只覆写**名录**的
  `camp`/`camp_name`，详情 `camp` 保持源数据；父级码保留作未来新角色兜底。

## 3. 养成系统（最易混淆的三个）

这三个是**互相独立**的养成系统，等级都只是解锁门槛，**都不自动并入基础面板**：

| 术语 | 是什么 | 数据键 | 边界 |
|---|---|---|---|
| **突破** | 等级分段提升 | `level`（key 1-6） | 它的加成**计入**基础面板（`hp_max`/`attack`/`defence` 是「至该段累计」的突破加成，不是单段增量） |
| **核心技强化** | 核心技的额外强化档 | `extra_level`（解锁门槛 `max_level` 15/25/35/45/55/60） | **不是**基础面板的一部分；`extra` 内的值是**累计万分比** |
| **潜能影画** | V2.5「激发潜能」系统 | `potential_detail` / `potential` | **与核心技强化是两个系统**，不要混为一谈 |

- **核心技（`passive`）**：核心被动 + 额外能力，有 7 级 / 14 级两轮强化版。
  **边界**：它是技能本体，与「核心技强化」（`extra_level`）是**不同**的东西。

### 技能等级上限（12 与 16 是两件事）

技能等级的**基础**上限是 **12 级**，这也是站内滑条的**默认**等级（打开详情页看到的就是
Lv.12）。**影画 3 与影画 5 各带一条「技能等级+2」**，把可达上限抬到 **16 级**。
三个数各有各的名字，代码里也是三个常量，**不要互相顶替**：

| 概念 | 值 | 常量 | 用途 |
|---|---|---|---|
| 基础上限 | 12 | `SKILL_LEVEL_MAX` | 技能本身能升到的等级 |
| 默认展示等级 | 12 | `SKILL_LEVEL_DEFAULT` | 滑钮初始位置；误用上限会让页面一打开就显示 16 级 |
| 实际上限 | 16 | `SKILL_LEVEL_CAP` | 滑条可达的最高级（基础上限 + 影画加成 `MINDSCAPE_SKILL_LEVEL_BONUS`） |

**边界**：
- 影画加成的作用范围是**除核心技外**的全部技能槽位。文案只列到「[普通攻击]、[闪避]、
  [支援技]、[特殊技]、[连携技]」，**终结技虽未被列出也吃这份加成**——它与连携技同处一个
  升级节点（`skill.chain` 槽、共用同一份 `material`），共享同一个等级。
- **核心技不受影响**：它是独立系统，1–7 级（见 `buildCoreSkill`），滑条上限固定 7。
- **邦布不受影响**：上限由数据自带的 `levelCount` 决定（主动技/连携技 10、额外能力 5）。

**数值口径**：13–16 级的倍率按同一成长公式**线性外推**（`main + growth*(lv-1)`），
数据里也只有 12 档 `material`、不含高等级档位。已核对：安东普通攻击 Lv.16 一段
伤害倍率 160.8% / 失衡 57.9%，与站外 wiki 的 Lv.16 技能表**逐项一致**。

## 4. 数值换算（避免误读）

- 百分比类字段（`crit`/`crit_damage`/`pen_rate` 等）在数据里是 **×100** 的整数：
  `crit = 500` 读作 **5.00%**。
- `{CAL:expr,scale,decimals}` 的 `scale` 语义须按游戏实机核实：小数式 **×100 转百分比**
  （如 月城柳极性紊乱满级 3200%）。**不要凭字面推**。
- 属性成长公式（已用「11号」Lv.1041 锚点验证）：

  ```
  属性(L) = floor( 1级基础 + 该段累计突破加成 + growth/10000 × (L-1) )
  ```

  分段判定为 `(level_min, level_max]`；段 1 的 `min = 0`；`Lv.60` 归段 6。

## 5. 四语名对照

**不在本文件。** 界面术语的四语写法（类目/板块、站点自撰用词）是
[决策记录 0011](../decisions/0011-multilingual-ui-copy.md) 的「四语名对照」节——那份决策的复核面。
本文件只管**术语的定义与边界**（单语），四语写法见 0011。

一条边界值得留在这里：属性/职业/攻击类型的中文列是**站内短式**（源站写「火属性/冰属性」），
其余三语取源站原值；`en` 列同时是构建管线写入英文枚举值的来源（`scripts/build/normalize.ts`），
改它等于改数据面。值本身归 `src/domain/enums.ts`，契约由 `tests/ui-text.test.ts` 钉住。
