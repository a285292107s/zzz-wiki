## 0. 结论（先给答案）

直觉**对一半**。

- **「e2e 太累赘」的直觉，指错了对象**：29 个浏览器脚本里 **23 个确实只有浏览器能看见**
  （判定 a），删掉就是真丢覆盖——历史上有 ≥25 条真实缺陷实绩记在它们名下（几何/逐帧、无障碍、
  交互反馈、命中区、声明一致性各占一部分；§5 有台账与口径说明）。真正该砍的不是这些检查。
- **累赘真实存在，但长在另外四个地方**：①**注册表税**（加一条路由要人工同步 26 份清单）；
  ②**伪覆盖**（9 处「宣称检查了、判据根本没判」+ 23 个「扫到 0 条也绿」）；
  ③**跨层重复**（`regression-walk.js` 四段与专项审计重复、4 项检查与单测重复）；
  ④**零门禁**（29 个脚本 100% 手工，`build:ci` 不跑、唯一 workflow 也不跑 →
  你花的是真金白银的注意力，换不到自动拦截）。
- **最便宜的一次收益不是删检查，而是补判据**：把 9 处「收集了字段从不判定」接进门禁、
  给 23 个脚本加非空守卫，**不动一个检查项**就能把真实覆盖率显著提高（§4 P0）。
- **重复该消，但不是现在照单删**：§3.3 的 4 项合并候选，经独立复核**5/5 都需要前置条件**
  （直接删会各自丢掉一块真覆盖，例：删 `landmarks` 后丢 `<footer>` 无人查、删 `slider-keyboard`
  后 8 根滑条只剩 1 根被测）。**先补覆盖，再删**（§4 P3）。

一句话版判据：**一条检查只该存在于「它能看见的唯一那层」，且必须真跑、真有判据、有下限。**

## 1. 第一性原理：一条检查凭什么存在

### 1.1 期望价值

```
V = P(缺陷发生) × P(这条检查能抓到) × Cost(漏到线上的代价)
      − [ 编写 + 每次运行 + 维护/连带改动 + 误报消耗 ]
```

关键在**最后一项**。一条检查的"编写成本"是**一次性**的；"运行 + 维护成本"是**每次改动都要付**的。
这就是为什么一个检查的价值不取决于它写得多漂亮，而取决于**它绑定的面向未来是否稳定**。

### 1.2 成本结构（本仓库实测）

| 成本项 | 本仓库实测 |
|---|---|
| `pnpm test` 全量（502 用例 / 50 文件） | **≈8.5–11.1 秒**（两次单点测量：11.09s / 8.49s；vitest 自报 6.83–9.02s），退出码 0。**不是稳定基线**，只作量级 |
| 单个浏览器脚本（`viewport-overflow.js`，72 次导航） | **52.38 秒**（首跑 14.46s 因 `Execution context destroyed` 失败） |
| 最大的浏览器脚本（`regression-walk.js`，97–98 项） | 两次都没跑完（17.66s / 51.27s，**两种不同错误**）→ 全绿耗时**未测** |
| 全量 29 脚本（`pnpm run audit:all`） | **未测**（需浏览器 + preview，超出本次时间盒） |
| 结论 | 单测层十秒级可全量跑；浏览器层是**分钟级、且环境敏感**的 |

### 1.3 各层能"看见"什么（能力矩阵——这是"该写在哪"的唯一第一性原理）

| 层 | 能看见 | 看不见 |
|---|---|---|
| 类型系统 / tsc | 类型、契约、穷尽性 | 一切运行时行为 |
| vitest(node) | 纯函数、解析、排序、公式、数据不变量 | DOM、布局、媒体查询 |
| 构建期数据校验 | 全量数据的事实（计数、外键、字段） | 渲染结果 |
| jsdom（vitest） | DOM 结构、类名、状态机、交互语义 | **排版引擎**：几何恒 0、`:hover` 不解析、`matchMedia`/`IntersectionObserver`/`scrollWidth` 全靠 mock |
| 真实浏览器 | 真实排版、逐帧几何、字体度量、媒体与渲染模式、网络与缓存、跨页旅程 | 数据管线；且**跑得慢、环境敏感** |

**推论（本报告的核心切分轴）**：判断一条检查该不该留在浏览器，不看它是"整页还是单组件"，
而看**这条断言的真值要不要真实排版 / 渲染模式 / 网络 / 跨页状态**。要，就只能在浏览器；
不要，就下移到最便宜的能看见它的那层。

**反例（两头最差的做法）**：把"需要真实排版"的断言放进 jsdom，靠 mock 造出几何再断言自己造的值
——继承了 e2e 的脆，没有单测的稳。本仓库确有此形态（§3.4）。

### 1.4 两条针对"个人项目 + AI 辅助"的修正

1. **AI 让"写"变便宜，让"维护"没变便宜**。脚本从 10 行涨到 200 行几乎零成本，于是检查数量会
   自发膨胀到远超人的判读能力；而每次改源码要连带改的测试/审计行数**不因 AI 而下降**。
   因此约束应加在**变更放大**上，不是加在"能不能写出来"上。
2. **AI 修红灯的默认动作是改测试**。一条判据含糊、环境敏感、或靠几何反推的检查，在 AI 手里
   会被"修绿"而不是"修真"——**检测器退化成橡皮图章**（本仓库 README 已记录 4 类假绿事故）。
   因此判据必须**正向化 + 有下限**（"必须有 N 项、N 项全过"），而不是"异常数为 0"。

### 1.5 五条存在判据（C1–C5）与门禁资格

- **C1 唯一可观测性**：该性质在更低层结构上看不见。
- **C2 真实变异存在**：过去真的改过/会改这块（有 git 证据），不是假想风险。
- **C3 判据可信**：判据是**正向断言 + 下限**，不靠"计数为 0"；失败信息能定位。
- **C4 绑不变量，不绑快照/实现**：改一处实现不该让一堆检查变红。
- **C5 不与其它层重复**：同一事实只在一层被断言。
- **门禁资格**：**跑不到的检查等于不存在**。一条检查若不在任何自动门禁里、也不在触发时必然
  被跑的工作流里，它的期望价值按 0 计（无论写得多好）。

### 1.6 负价值四形态（发现即处理）

| 形态 | 表现 |
|---|---|
| S1 重复 | 同一事实在两层各测一遍；改了实现，两边都要改 |
| S2 自证 | mock 造出输入，再断言 mock 造出的输出 |
| S3 快照耦合 | 绑 DOM 结构/类名/文案，实现动一下就红 |
| S4 假绿 | 判据不完备或没有下限，扫描范围塌缩时静默通过 |

## 3. 判定：哪些真的需要浏览器，哪些不需要

判定分布（29 个脚本逐项实读）：**a 23 / b 1 / c 4 / d 1**。

### 3.1 必须留在浏览器（a 类，23 项）——按"它独有的观测"归成 6 类

| 能力类别 | 脚本 | 它独有的观测（更低层为什么看不见） |
|---|---|---|
| **真实排版几何** | `viewport-overflow`、`touch-targets`、`reflow-spacing`（1.4.10/1.4.12 部分）、`spacing-audit`、`composition-audit` | 横向溢出、命中区尺寸、重排后裁切是排版引擎的输出；jsdom 的 `scrollWidth` 只能打桩自证 |
| **逐帧 / 过渡几何** | `hero-flight`（视图过渡共享元素飞行）、`motion-audit` | 需要真实动画帧与过渡进度；`tests/` 全仓 0 处 `prefers-reduced-motion` |
| **真实字体与字重** | `font-weight-calibration`（Canvas 逐像素比墨量）、`typography-audit`（级联后的计算值） | 字体是否被系统字体顶替只有渲染能答；源码扫描只覆盖声明处，覆盖不了继承链 |
| **UA 渲染模式** | `print-mode`、`forced-colors` | 只有 `emulateMedia` / UA 强制替换渲染能给出纸面与高对比度的真实结果 |
| **网络与缓存** | `transfer-profile`（冷启动传输预算）、`offline-check`（SW + `setOffline`）、`csp-check`（运行时是否真被拦）、`inp-interaction`（4 档 CPU 节流） | 传输量、离线可用性、CSP 拦截、交互延迟都是真实网络/CPU 的读数 |
| **全站遍历与跨页旅程** | `content-sweep`（238 页，清单取自 sitemap）、`keyboard-journey`（19 条纯键盘任务）、`axe-a11y` / `axe-states` / `ax-tree`（真实无障碍树）、`color-audit`（计算色与继承链）、`interaction-states`（CDP 强制 `:hover/:active`）、`focus-visible`（130 个 Tab 停靠点的焦点指示） | 跨页状态、真实无障碍树、`:hover` 层叠结果、焦点轮廓计算值 |

上表 5+2+2+2+4+8 = **23 项，即台账判定 a 的全部**。另有 2 个脚本被判 **c（重复）**，但它们各有一段
**浏览器独有、不能一起删**的部分，故拆出来单独说明、**不计入这 23 项**（否则与 §3.3 重复计数）：

| 在 c 类脚本内部保留的部分 | 保留理由 |
|---|---|
| `section-nav` 的几何/蒙版/命中区/高对比度段（`:103-114,145-161,163-175,178-186,188-229`） | 吸顶横条的滑动停靠点与蒙版宽度是排版输出；只有它的状态机部分与单测重复（§3.3） |
| `regression-walk` 的跨页链路 + 数据真值比对（`:32-49`） | 跨页状态与"页面声明 vs 实际数据"是别处没有的观测；它的四段重复交给专项脚本（§3.3） |

这 23 项**不建议删**。它们是"个人项目也能拿到竞品级品质"的实际来源（§5）。

### 3.2 可降级（b 类，1 项）
