# 共享元素过渡（View Transitions API）

首页「今日角色」牌堆里的立绘 → 代理人详情页头图，两块用的是同一张
`Mindscape_{id}_2.webp`。让**那张画自己飞过去**（首页陈列框 1029×430 → 详情整栏
1168×413，位移与缩放同时发生），这就是 Web 版的 flutter `Hero`。

```
首页                                        代理人详情
┌ .deck-frame ───────────┐   点卡     ┌ .ahead ─────────────────┐
│ ┌ .deck-item ─────────┐│ ───────→ │  .hero-bg ← 共享元素    │
│ │  画  ← 共享元素     ││  返程     │   (zoom 校准含在其中)   │
│ └─────────────────────┘│ ←───────  │  压暗面 / 四角标 / 文字 │
│  标本签 / 座次刻度      │           └─────────────────────────┘
└────────────────────────┘
        └──── view-transition-name: deck-frame ────┘
```

## 一趟完整的编排是四拍

```
点击
 ├ ① 整页退场    首页可视区块自上而下依次收走（data-vt-block 声明，chrome.ts 收集）
 ├ ② 原地变形    那张画在原地把取景从「牌堆校准」变成「目的地取景」（纯 transform）
 │              └─ ① ② 是**同一拍**：变形时长按退场错峰实时算（--vt-morph）同时收尾，
 │                 再过 40ms 余量才 push 导航
 │              └─ **窄屏（≤860）跳过这一拍**：目的地取景 == 卡片自己的校准取景，见下节
 ├ ③ 飞行        460ms：View Transitions 插值盒的几何：933×395 → 1168×413
 └ ④ 逐条入场    目的页区块按同一份错峰索引自上而下装订（延后 300ms 起，落在飞行尾段）
                （采样期它们不进新快照，落地前后才动）
```

## ② 只在宽屏做（窄屏做了反而错位）

变形的目标值是**桌面详情页的取景**（整栏、纯 cover 居中、不套校准）。只有桌面下它才等于降落端，
所以它值得那一拍。**窄屏不成立**：AgentHead 手机端的头图**复用同一份** `pos/zoom/originY`，
目的地取景本来就等于卡片自己的取景 —— 于是把画切到中性态（`pos 50% / originY 50% / scale 1`）
是把它**推离**目的地。实测（390×844，同一张 `Mindscape_1541_2`，可见源图分数区间）：

| 状态 | 可见源图区间（x / y） | 与降落端 |
| --- | --- | --- |
| 卡片·校准态 | 0.5177–0.8646 / **0–0.7722** | ✅ 逐像素相同 |
| 卡片·变形目标（中性） | 0.2754–0.7246 / **0–1.0** | ❌ 纵向差 1.295× |
| 详情页头图（降落端） | 0.5178–0.8646 / 0–0.7722 | — |

交接处那一跳 `1/0.7722 ≈ 1.295×` 恰好等于该图 `zoom` —— 也就是说，
**这个「飞到最后啪地换了个大小」正是变形在窄屏自己造出来的**（它本是用来消除这个的）。
故窄屏跳过 ②：让画保持校准取景飞过去，交接零错位。

判据收在 `src/utils/deckFraming.ts`（纯函数，可单测）：`deckFigureStyle(calibration, morphing, narrow)`
在 `morphing && !narrow` 时才返回目的地取景。断点 860 由组件经 `useMediaQuery` 给出
（与 CSS/tokens 同一条查询），该模块不重复声明断点数字。

实测复验（`hero-flight.js` K 项，390×844，采样卡 zoom=1.29652）：

| 时刻 | 起飞端 scale | 目的地 scale |
| --- | --- | --- |
| 常态 | 1.29652 | — |
| 离场前（进快照那一刻） | **1.29652**（未变形） | 1.29652 |

窄屏若退回旧行为，第二行会变成 `1.000`，与目的地的 `1.29652` 差 1.295× —— 审计即报红。
宽屏仍照旧（同一份审计的第 6 项：`startScale 1.29652 → endScale 1`）。


**节奏的三条硬约束**（都是「去程不如回程顺」那次实测倒推出来的）：

| 约束 | 数值 | 不满足会怎样 |
| --- | --- | --- |
| ① 与 ② 同时收尾 | `--vt-morph = 错峰总长` | 变形 300ms 就停、退场还要走 412ms → 起飞前 **~140ms「页面已空、画也不动」的死档** |
| 准备期封顶 | `EXIT_CASCADE_CAP_MS = 420`（区块多就压小错峰步长） | 16 块的页面准备期 500ms+，观感是「清空很久才飞」 |
| 落点不能空 | `inHold 300` < 飞行 460 | 落地那一刻首块才刚开始（旧值 300 + 飞行 400 → 落地后还要等 347ms 才有东西显形） |

还有一条**曲线**的坑：变形最初沿用全局 `--ease`（强 ease-out），实测 420ms 的过渡在 ~300ms
就「看起来停住」（前 70% 时长跑掉 98% 的进度），死档照样存在。取景三条现在用
`cubic-bezier(0.4, 0, 0.2, 1)`（中段饱满），整段准备期里画一直在变。

## 回程为什么天然更顺（同一次飞行的两种密度）

| | 去程 home→detail | 回程 detail→home |
| --- | --- | --- |
| 起跳耗时 | 388ms（退场 + 变形，即用户要求的「先变形」） | 43ms（浏览器返回，无法预编排） |
| 起跳时**源端**快照 | 被退场清空（6 块全 0）；站头原样在台上 | 详情页**整页还在**，随根交叉溶解退场 |
| 起跳时**目的端**快照 | 被入场编排藏空（6 块全 0）；站头原样在台上 | 只藏 1 块（标本签）；站头同样在台上 |
| 观感 | 内容两端都空 → 一张画在「终端框架」里飞 | 快照里有内容在溶解 → 飞行「有信息量」 |

结论：去程那一段的密度天生低于回程，**补法是把常驻外壳（站头/站尾）留在台上**
（`data-vt-hold`，见下），它让飞行有了"不变的框"；页面内容仍然照旧全退全入。

**为什么需要 ②**（宽屏）：飞行中的两层是**位图快照**，浏览器只插值几何、不插值内容 —— 两端取景
不同就只能靠交叉溶解交接，而溶解那一刻两层的内容尺度比正好等于牌堆的校准 zoom
（1.2–1.49×），看起来就是「飞到最后啪地换了个大小」。把取景变化挪到**起飞前、在活的
DOM 上**做，任何属性都能连续插值；留给 VT 的只剩纯几何位移。

**但这条推理的前提是「两端取景确实不同」**——桌面成立、窄屏不成立（见上一节）：
窄屏两端复用同一份校准，变形反而**制造**了那个 1/zoom 的尺度跳。判据在 `utils/deckFraming`。

## 全页退场：为什么是声明而不是自动识别

区块由组件用 `data-vt-block` 自己声明（`chrome.ts` 只负责按视觉顺序编号 + 标记 + 清理）。
自动判据试过并放弃：实测把站头拆成六个标签、把 hero 那排 meta 拆成带点的碎块，两页都收到
上限件、详情页覆盖率还只有 53%（主内容都没轮到）。**编排粒度是艺术决定**，不该由几何猜；
漏标一个新区块由 `hero-flight.js` 的区块数与覆盖率断言兜住。

同一套标记一共三个，语义边界都写在 `chrome.ts` 顶部（那里是定义处，这里只列用途）：

| 标记 | 用途 | 挂在哪 |
| --- | --- | --- |
| `data-vt-block` | 参与退场/入场的可视区块 | 首页 hero 各行、区块标题、目录行、标本签；详情页四角标、档案行、身份块… |
| `data-vt-skip` | 让位：本块含主角（那张画/头图），整块不淡，改由「装裱壳」只退边线底色 | 牌堆那张画、详情页压暗面 |
| `data-vt-hold` | 常驻外壳：**不进任何计划**（不退场、不被入场藏起） | 站头、站尾 |
| `data-vt-fade` | 导航类：**仍在计划里，但只淡不位移** | 详情页「返回」、区块索引 |

**`data-vt-fade` 是"左侧导航条跳一下"查出来的**：导航家具跟着内容一起 `translateY(12px)`
进场时，宽屏那条**固定轨道**（`left` 固定、`top: 50%` + `translateY(-50%)` 垂直居中）会被
关键帧的 `to { transform: none }` 覆盖掉居中变换 —— 实测 1920×1080 下轨道稳态 `top=345`，
挂上旧入场动画时坐到 `top=540`（低 195px），编排收尾清标记那一刻再**弹回 345**。
现在换成只动 opacity 的关键帧，轨道全程 `transform` 恒为 `translateY(-195px)`、`top` 恒定。

**`data-vt-hold` 是"去程节奏"那次实测带来的**：站头若参与编排，飞行期间两层快照里它都是缺的
（源端已退场、目的端被藏起），观感是"整块丢了一下"；标记 hold 后它在两层快照里都是原样原位，
根交叉溶解叠上去等于不变 —— 终端不动、只有页面内容在换。实测去程起跳时/落地时站头都是
`opacity 1.00` 且不在入场名单里（此前两处都是 `0.00`），退场区块数也相应 7 → 6。

时序常量（`VT_TIMING`）是 CSS 与 JS 的单一来源：模块把它们写成 `--vt-*` 挂在 `html` 上，
JS 侧按同一组数字算「该等多久」，避免"界面 300ms、JS 只等 200ms"。

## 五个必须处理的坑（都实测踩过）

1. **跨路由常驻的 chrome 别让它带妆飞**：站头/站尾不在 RouterView 里，导航不会重建它们。
   现在的正解是 `data-vt-hold`（见上）；早期做法是"采样前把退场态交棒给入场编排"，
   那会在飞行期间把站头整段藏掉 —— 已废弃。
2. **中途改主意必须赢**：编排进行中点了别的链接，若不管，编排落定后的那一跳会盖掉用户的
   新去向（实测确实飞到了旧目的地），退场标记还会留在页面上（站头保持隐身）。
   修法：`beforeEach` 里发现目标不是本次编排的目的地 → 整段撤销 + 回滚。
3. **修饰键永远放行**：⌘/Ctrl/Shift/Alt 与中键点击是「新标签打开」的正常语义，被拦下来
   是可用性事故。点击接管只认无修饰的普通左键（键盘 Enter 走同一条浏览器 click 路径）。
4. **接管必须在捕获阶段**：`@click.capture` 挂在取景框上 —— vue-router 的链接处理器会先
   `preventDefault` 并 push，冒泡阶段再拦已经晚了。
5. **退场要「加速离开」+ 步长够大**：用全局 `--ease`（强 ease-out）会在头 40ms 就淡完，
   错峰等于不存在；改成 ease-in 家族 + 26ms 步长，7 块约 380ms，级联才读得出来。

## 为什么挂在「裁切容器」上

名字的落点选错过两次，教训都留在代码注释里：

| 挂在哪 | 结果 |
|---|---|
| 装裱框 `.deck-frame` | 框与详情头图尺寸本来就接近，挂框只会「整块面板挪一下」——**看不出是飞行** |
| `<img>` 本体（`vt-name` prop，已回退） | `<img>` 带 zoom 校准 transform，渲染盒比可视区域大 28%；带名元素的快照不含祖先的 `overflow: hidden` 裁切，**起飞瞬间凭空放大一圈** |
| ✅ 可视裁切容器：`.deck-item` / `.hero-bg` | 各自 `overflow: hidden`，快照=用户看到的画面；起飞盒与落点盒的几何差即观感 |

**推论：凡是「属于这张画观感」的东西，都必须放进这个裁切容器里。** 详情页的压暗层
（`.scrim`，底部深掩埋保证文字可读）原先挂在 `.hero-bg` 外面，于是它属于「页面」快照，
而具名组的伪元素画在根快照**之上** —— 飞行期间那张画把压暗层盖住，落地那一刻才露出来。
实测（纯画面区逐帧亮度）：**落地后单帧亮度塌陷 72 点**（145 → 73），观感就是「飞完突然变暗」。
把 `.scrim` 放进 `.hero-bg` 之后，压暗随共享元素的新旧快照交叉溶解逐步加上去：
同一区域峰值由 145 降到 100、单帧最大变化由 −72 降到 −13、终态不变（72.6 vs 72.8）。
溶解窗口也从 200ms 拉到 260ms（延迟 120ms）—— 它同时承载「取景交接」与「压暗加上去」两件事，
窗口太短会退化成一次快速变暗。

## 装裱壳：只退「自己的」边线与底色（别给透明层凭空涂色）

`vt-chrome-case` 是按**共享元素的所有祖先**标记的（`chrome.ts` 的收集规则），首页那张画有
**13 层**祖先、一路到 `body`。其中绝大多数**本身完全透明**（`#app` / `.shell` / `#main` /
`.home` / `.eb-root` / `.wrap` …），真正自带框的只有 `.deck-frame`（1px 边线 + 不透明底色）
与详情页的 `.ahead` / `.wrap.page`。

所以 `vt-case-*` 关键帧**只能写一侧**（隐式关键帧），另一侧取元素自身的计算值：

| 写法 | 结果 |
|---|---|
| ✅ `from`/`to` 只写透明那一侧 | 透明层 from==to==透明（no-op）；带框层从**自己的**底色退到透明 |
| ❌ 两侧都写死 `--bg-0` / `--line-1` | 给 10 层透明包装层**凭空涂上整页底色** |

坏写法造成的正是「飞行前后背景闪了好几下」（实测 4 次跳变）：

1. 点卡瞬间：`#app .shell #main .home .eb-root` 等 5 层被涂到 `alpha≈1.00`
   —— `.home` 一被涂就盖住固定层 `.home-backdrop` 的拼贴壁纸；
   `#app`（z-index:1）一被涂就盖住 `body::before` 的页面壁纸；
2. 退场期间：涂层淡出 `1.00 → 0.02`，壁纸淡回；
3. 落地（`vt-landed`）：4 层又被从透明涂到 `alpha 1.00`，壁纸再次被盖住；
4. 摘类那一刻：涂层「啪」地消失，壁纸又跳回。

A/B 实测（同一构建，B 组注入旧关键帧复现）：

| | 被涂色的帧数 | 单帧最多被涂层数 |
|---|---|---|
| 隐式关键帧（现行） | **0 / 121** | **0** |
| 写死整页底色（旧） | 32 / 121 | **10**（`#app .shell #main .home .wrap .banners .featured-deck .deck-track .deck-slide`） |

顺带修掉一处旧偏差：`.wrap.page` 的自然底色是 `--bg-1`，旧关键帧却把它拉到 `--bg-0`
再在摘类时弹回 —— 隐式关键帧天然没有这个问题。

⚠ **反向护栏**（`hero-flight.js` 的 M 项）：收窄后必须确认装裱壳**仍在工作** ——
退场期 `.deck-frame` 的底色要真的降下来。否则「不闪了」可能只是把壳整个关掉了。

## 一次飞行的时序

```
点击 <RouterLink> → vue-router 导航
   beforeEach            回程判定（服务 App.vue 的页面过渡让位）
   beforeResolve         「首页 ↔ 代理人详情」才起跳，其余一律走普通导航
     ├ 登记起飞卡         rememberDeckCard(params.id) —— 回程落回同一张
     ├ 预热降落端头图      详情档地址（与首页卡片不同档、不同缓存）
     ├ startViewTransition(更新回调)
     └ await 更新回调已开始  ← 旧状态此刻才进快照，这里放行导航
         └ 更新回调         放行 → 路由落定 → nextTick → 挂 vt-landing → 等画可绘制 → 让出宏任务
         导航落定后 DOM 更新 → 浏览器采样新状态 → 伪元素上插值（460ms）
     finished              撤 vt-active / vt-landing；vt-landed 交给自己 900ms 的定时器
```

## 六个不显眼但会致命的地方

1. **守卫必须等「更新回调已开始」才放行导航**（双向闸门）。
   浏览器在**下一次渲染时机**拍旧状态，而 vue-router 的 DOM 更新在微任务里 —— 放行早了
   旧快照拍到的就是**已经切完的画面**：两端几何完全相同，整段飞行退化成一次看不见的
   交叉溶解。实测数据：group 盒从第一次采样起就是落点尺寸 `1168×413 @ (136,285)`，
   而正确实现是 `1029×430 @ (205,207)` 逐帧收敛到落点。
   反向的坑同样致命：守卫里 `await` 整段过渡 → 导航等不到放行、回调等不到 DOM，
   两张快照都拍旧页面（同样是空转）。
2. **更新回调里不能用 `requestAnimationFrame` 等「一帧」**：浏览器在跑更新回调期间会
   暂停渲染循环（实测 Chrome 整整 4s 不派发，直到它自己的 *DOM update timed out*
   把过渡判废）。必须用微任务/定时器级别的让出（`settleAfterPaint`）。
3. **每一次等待都要有上限**：路由落定 `NAV_SETTLE_MS`、图画可绘制 `SHARED_READY_MS`、
   起飞前预热 `LANDING_PREWARM_MS`。超时**不是错误**：放行、照常播，绝不把
   `vt-active` 永久挂在 `html` 上（那是「页面过渡被永久停用」的事故）。
4. **新状态那端的画必须先就绪**：首页卡片走 `card/wide` 派生档，详情按 DPR 走原图或
   `mobile/` 派生 —— **地址不同、缓存不共享**。不预热/不等待，浏览器采样到的是空画布：
   实测帧序列里 320ms 全黑、随后硬切到详情页（「看不出动画」的真身）。
   预热地址与渲染地址共用 `data/heroImageSources.ts` 一份规则，算错档位等于白下一张。
5. **`mode="out-in"` 与共享元素互斥**：新视图的 DOM 更新会被压后 260ms，采样要么拿到旧
   画面、要么拿到全透明新页。根类 `vt-active` 期间停用页面过渡（App.vue）。
6. **root 组的整页交叉溶解必须等长线性互补**（old 1→0 与 new 0→1 同步、透明度和恒为 1）：
   只给 0s 时长不给 fill-mode 时，旧页快照以 `opacity: 1` 盖到飞行结束，结尾「啪」地硬切；
   两段时长不等时 `plus-lighter` 和≠1，中段会提亮。

## 编排：三拍，不是一次交叉溶解

节奏收在 `src/styles/base.css` 的 `::view-transition-*` 与 `vt-plate-in`：

| 时间 | 发生什么 | 归属 |
|---|---|---|
| 0–460ms | 画从陈列框长到整栏（中段饱满的 ease-in-out；早前试过的 expo-out 已弃用） | `::view-transition-group` |
| 120–380ms | 两个裁切快照等长线性互补交换（延时 120ms + 时长 260ms） | `::view-transition-old/new` |
| 0–240ms | 两端页面其余部分交叉溶解（旧标本签随之退场） | `::view-transition-old/new(root)` |
| 采样时 | 目的页文字层**不进新快照**（`vt-landing`） | `html.vt-landing` |
| 250–640ms | 框标 → 档案行 → 身份块逐条就位（`vt-plate-in`） | `html.vt-landed` |

回程同理，且**落回起飞的那张卡**：起飞时登记卡片 id，首页牌堆挂载时取走一次
（`consumeDeckCard`）——否则 A 的画会飞进 B 的框里（两个角色的交叉溶解，比不飞更糟）。
牌堆自己的「标本装匣」入场编排在这趟里让位（见 FeaturedDeck 的 `is-mounting`）。

## 名字挂在哪 / 标记挂在哪

| 用途 | 元素 | 何时 |
|---|---|---|
| 共享元素名（浏览器读） | 首页活动卡 `.deck-item`、详情 `.hero-bg` | 常驻（仅活动卡）；四张都挂会重复名，浏览器跳过整次过渡 |
| 端点标记 `data-vt-shared`（运行时读） | 同上 | 常驻；回调用它找到**新状态那端的画**并等它可绘制 |
| `vt-active` | `html` | 起飞前 → finished（页面过渡让位） |
| `vt-landing` | `html` | 采样前挂、finished 撤（把文字层挡在新快照之外） |
| `vt-landed` | `html` | 采样后挂、900ms 后自撤（落地编排的开关） |

## 怎么降级

| 情况 | 行为 |
|---|---|
| 浏览器无 `document.startViewTransition`（Firefox < 144 等） | 不注册守卫、不加根类、不发内联名；导航与页面过渡完全退回原样（启动时无 `[viewTransition]` 日志） |
| `prefers-reduced-motion: reduce` | 安装期就短路（伪元素不在 base.css 那条全局降速的 `*` 作用域里）；牌堆入场编排也不启动（全局只归零时长、不归零延迟） |
| **起飞端基本看不见（露出 < 10%）** | **不飞**：挂 `data-vt-no-flight="<起飞端>"` 摘掉那一端共享元素名，只剩落点那张画的一次淡入 + 根交叉溶解（见下节） |
| 别的一对路由（名录 ↔ 详情、同类目详情互跳、其它页） | 判据直接跳过，不调 API |
| 飞行中再次导航 | 并进同一次过渡，不叠第二次 `startViewTransition`；导航被打断也照常撤标记（实测点卡后 120ms 再点名录：落在 /agents，无残留类） |
| 键盘激活（焦点 + Enter） | 与点击同一条路径，飞行照常（实测 group 逐帧收敛） |

排查「没看到动画」：控制台看有没有 `[viewTransition] 共享元素过渡已启用`。
没有这行 = 浏览器不支持该 API，或用户在系统里开了「减少动态效果」。
**有这行却没飞**：看 html 上有没有 `data-vt-no-flight` —— 那说明起飞端当时没露在屏上，是设计如此。

## 起飞端不在屏上：为什么不飞

浏览器把带名元素**在文档里的盒子**直接映射到视口坐标，**不看它在不在屏幕上**。于是详情页
滚到底部再返回首页时，`.hero-bg` 位于视口上方约 9800px，整段飞行就从那里开始：

| 详情页滚动量 | 头图可见比例 | 起飞盒起点 y | 视口外路程占比 | 视口外时间占比 | 判定 |
|---|---|---|---|---|---|
| 0（顶部） | 1.00 | 282 | 0% | 0% | 飞 |
| 400px | 0.71 | −118 | 12% | — | 飞 |
| 500px | 0.46 | −218 | 22% | — | 飞 |
| 700px | 0 | −418 | 39% | — | **不飞** |
| 到底 | 0 | **−9650** | **91%** | **67%** | **不飞** |

（1440×900、`/agents/1541`；手机 390×844 同量级：起点 y=−11775。）

观感因此是「一张画从视口上缘凭空滑进来」，而不是「这张画从刚才的位置飞过去」。
判据与阈值收在 `config.ts`：

- `FLIGHT_MIN_VISIBLE_RATIO = 0.1`：判据的语义是「**基本看不见**」，不是「没看全」。
  取值被实测的两条约束夹住：
  - **上限（别误伤）**：常见视口的比例下界是 0.19（320×568 牌堆只露一角）、0.40（844×390 横屏
    牌堆贴顶边）、0.48（844×390 详情页头图）—— 这些位置上人正看着那张画，判掉就是可用性事故。
    尤其横屏：牌堆高 968px 而视口仅 390px，**任何阈值 > 0.5 都等于把横屏的去程飞行整个关掉**。
  - **下限（必须拦住）**：完全滚出视口（比例 0）时飞行有 39%–91% 的路程在屏幕外。
- `flightSourceVisible(end)`：**量不出来时按「飞」处理** —— 元素缺失 / 无 DOM 环境一律放行。
  宁可多飞一次，也不要因为一次量测失败就把正常飞行静默关掉（那正是本站
  「静默空转」同类事故的形态）。
- 点击入口（`canArmDeckFlight`）与守卫**用同一份判据**：入口决定「要不要花 400ms 演整页退场
  + 取景变形」，守卫决定「飞不飞」。两者不一致就会出现「编排演完了却决定不飞」的空拍 ——
  用户白等 400ms 看页面清空，只换来一次普通溶解。

降级的实现是**摘掉起飞端那一端的名字**，而不是两端都摘、也不是不调 `startViewTransition`：

| 做法 | 结果 |
|---|---|
| ✅ 只摘起飞端 | 不再生成 `::view-transition-group(deck-frame)`，没有几何插值；`::view-transition-new` 仍在，落点那张画照旧按 260ms/120ms 淡入；根交叉溶解、站头不动、落地逐条入场全部保留 |
| 两端都摘 | 连落点那次淡入也没了，落地会「啪」地出现 |
| 不调 `startViewTransition` | 丢掉两端等长互补的整页溶解与「终端不动」，退化成 Vue 的 `out-in` 页面过渡 |

标记必须在 **`startViewTransition` 之前**挂上：浏览器在调用后的下一个渲染时机拍旧状态，
挂晚了赶不上那次采样（名字会照样进快照，等于白摘）。CSS 侧必须带 `!important` ——
两端的名字一处是内联样式（FeaturedDeck）、一处是组件 scoped 的静态声明（AgentHead），
层叠上都压不过。

**被否掉的替代做法**（都实测过）：

| 做法 | 为什么不做 |
|---|---|
| 起飞前先把详情页滚回顶部 | 几何确实正确（首帧 y=282、视口外 0%），但**旧状态快照拍到的就是顶部**：用户按下返回的瞬间，他正在读的那一段会被这一页自己的开头替换掉，然后才溶解走 —— 用一个没看过的位置充当离场画面，比不飞更糟 |
| 把起飞盒 transform 平移到视口边缘 | 几何也成立（首帧 y=0），但等于把「凭空出现一张大图」从飞行中段提前到第一帧，更显眼 |


## 怎么复验

飞行是**采样时刻**的事，无头截屏拍不到飞行中的伪元素（会拍到只剩背景的黑帧），
判定一律用「读伪元素的计算几何」：

```js
// 注入 6× 慢放后逐帧读 ::view-transition-group(deck-frame) 的 width/height/transform
// 正确：从起飞盒逐帧收敛到落点盒；错误（旧实现的空转）：第一帧就是落点盒
::view-transition-group(deck-frame) { animation-duration: 1920ms !important }
```
